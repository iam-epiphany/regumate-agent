# 根因分析与证据链开发教程

这个模块带你把“规则发现异常”变成“人可以复核的证据链”。证据链不是一句 AI 总结，而是一组结构化证据：哪条规则命中、哪个字段异常、制度依据是什么、可能根因是什么。

## 1. 最终要实现什么效果

输入规则结果：

```json
{
  "rule_id": "RPT_BALANCE_001",
  "passed": false,
  "expected": 8000.0,
  "actual": 7999.0
}
```

输出证据链：

```json
{
  "finding_id": "FINDING_001",
  "summary": "资产合计与分项加总不一致",
  "root_cause_candidates": [
    "填报模板公式漏计某个资产分项"
  ],
  "evidence_items": []
}
```

## 3. 第一步：定义证据 schema

文件：`backend/app/schemas/evidence.py`

```python
from pydantic import BaseModel


class EvidenceItem(BaseModel):
    evidence_type: str
    ref_id: str
    title: str
    detail: dict


class RootCauseCandidate(BaseModel):
    cause: str
    confidence: float
    supporting_refs: list[str]


class EvidenceChain(BaseModel):
    finding_id: str
    summary: str
    evidence_items: list[EvidenceItem]
    root_cause_candidates: list[RootCauseCandidate]
    recommended_action: str
```

## 4. 第二步：把规则结果转成证据项

文件：`backend/app/tools/evidence_tools.py`

```python
from backend.app.schemas.evidence import EvidenceItem


def build_rule_evidence(rule_result: dict) -> EvidenceItem:
    return EvidenceItem(
        evidence_type="rule",
        ref_id=f"RULE:{rule_result['rule_id']}",
        title=rule_result["message"],
        detail={
            "expected": rule_result.get("expected"),
            "actual": rule_result.get("actual"),
            "severity": rule_result.get("severity"),
        },
    )
```

## 5. 第三步：把制度 chunk 转成证据项

```python
def build_regulation_evidence(chunk: dict) -> EvidenceItem:
    return EvidenceItem(
        evidence_type="regulation",
        ref_id=f"REG:{chunk['chunk_id']}",
        title=chunk.get("title") or "制度依据",
        detail={
            "text": chunk["text"],
            "source_file": chunk["source_file"],
            "section": chunk.get("section"),
        },
    )
```

## 6. 第四步：生成根因候选

第一阶段用规则映射，不要假装模型已经能准确诊断。

```python
from backend.app.schemas.evidence import RootCauseCandidate


ROOT_CAUSE_MAP = {
    "RPT_BALANCE_001": "填报模板公式可能漏计或重复计算某个资产分项",
}


def infer_root_cause(rule_result: dict) -> RootCauseCandidate:
    rule_id = rule_result["rule_id"]
    return RootCauseCandidate(
        cause=ROOT_CAUSE_MAP.get(rule_id, "需要人工复核确认根因"),
        confidence=0.6,
        supporting_refs=[f"RULE:{rule_id}"],
    )
```

## 7. 第五步：组装完整证据链

```python
from backend.app.schemas.evidence import EvidenceChain


def build_evidence_chain(
    finding_id: str,
    rule_result: dict,
    regulation_chunks: list[dict],
) -> EvidenceChain:
    evidence_items = [build_rule_evidence(rule_result)]
    evidence_items.extend(build_regulation_evidence(chunk) for chunk in regulation_chunks)

    return EvidenceChain(
        finding_id=finding_id,
        summary=rule_result["message"],
        evidence_items=evidence_items,
        root_cause_candidates=[infer_root_cause(rule_result)],
        recommended_action="请复核报表模板公式、字段映射和填报口径。",
    )
```

## 8. 第六步：写测试

```python
from backend.app.tools.evidence_tools import build_evidence_chain


def test_build_evidence_chain():
    rule_result = {
        "rule_id": "RPT_BALANCE_001",
        "passed": False,
        "severity": "high",
        "message": "资产合计与分项加总不一致",
        "expected": 8000,
        "actual": 7999,
    }
    chunks = [
        {
            "chunk_id": "reporting_rules_sample#2.1#001",
            "text": "资产合计应等于资产分项金额的合计。",
            "source_file": "data/regulations/reporting_rules_sample.md",
            "section": "2.1",
            "title": "2.1 资产合计填报口径",
        }
    ]
    chain = build_evidence_chain("FINDING_001", rule_result, chunks)
    assert chain.finding_id == "FINDING_001"
    assert len(chain.evidence_items) == 2
```

## 9. 前端应该如何展示

异常详情页按层次展示：

1. 异常摘要。
2. 规则证据：期望值、实际值、严重程度。
3. 制度证据：制度片段和来源。
4. 根因候选：标注“候选”，不要写成确定事实。
5. 建议动作。
6. 人工复核入口。

## 10. 常见错误

- 根因写成绝对结论。
- 证据链没有制度来源。
- 只有自然语言，没有结构化字段。
- 前端无法从证据链定位到规则和制度。

## 11. 完成标准

- 规则结果能转换成 evidence item。
- 制度 chunk 能转换成 evidence item。
- 根因候选带 confidence 和 supporting refs。
- 异常详情页可以直接使用 EvidenceChain 展示。
