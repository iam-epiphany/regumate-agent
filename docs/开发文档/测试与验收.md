# 测试与验收开发教程

这个模块教你如何证明功能真的完成。不要只说“我试了一下可以”，而是要有自动化测试、手动验收步骤和清楚的通过标准。

## 1. 最终要实现什么效果

每个功能完成时都能回答：

- 跑了哪些测试？
- 测试覆盖了哪些成功和失败场景？
- 手动怎么验证？
- 还有哪些风险没覆盖？

## 2. 测试目录建议

```text
backend/app/tests/
  test_reports_api.py
  test_balance_rules.py
  test_report_tools.py
  test_filing_lint_agent.py
frontend/src/
  __tests__/
```

## 3. 第一步：先测健康检查

文件：`backend/app/tests/test_health.py`

```python
from fastapi.testclient import TestClient

from backend.main import app

client = TestClient(app)


def test_health_check():
    response = client.get("/health")
    assert response.status_code == 200
```

运行：

```powershell
pytest backend\app\tests\test_health.py
```

## 4. 第二步：规则必须有通过和失败测试

每条规则至少两个测试：

```python
def test_rule_passed():
    ...


def test_rule_failed():
    ...
```

比如资产合计规则：

```python
def test_total_asset_failed():
    row = {"cash": 1000, "loan": 5000, "bond": 2000, "total_asset": 7999}
    result = validate_total_asset(row)
    assert result.passed is False
    assert result.rule_id == "RPT_BALANCE_001"
```

## 5. 第三步：API 测试要覆盖错误情况

上传接口至少测：

| 场景 | 预期 |
| --- | --- |
| 上传 CSV | 200 |
| 上传 xlsx | 200 或按当前能力返回清楚错误 |
| 上传 exe | 400 |
| 不传文件 | 422 |

示例：

```python
def test_upload_unsupported_file():
    response = client.post(
        "/reports/upload",
        files={"file": ("demo.exe", b"bad", "application/octet-stream")},
    )
    assert response.status_code == 400
```

## 6. 第四步：Tool 测试要脱离 Agent

Tool 是 Agent 的积木。先单独测 Tool，再测 Agent。

```python
def test_parse_report_file_missing():
    result = parse_report_file("not_exists.csv")
    assert result.ok is False
    assert result.error.error_code == "REPORT_FILE_NOT_FOUND"
```

## 7. 第五步：Agent 流程测试

Agent 测试不要依赖真实大模型。第一阶段只测试固定 Tool 流程：

```python
def test_agent_completed_with_sample():
    state = run_filing_lint_agent("TASK_TEST", "data/samples/balance_invalid_total.csv")
    assert state.status == "completed"
    assert len(state.validation_results) > 0
```

## 8. 第六步：RAG 验收

RAG 的测试重点是引用，不是回答多漂亮。

验收问题：

| 问题 | 必须返回 |
| --- | --- |
| 资产合计怎么填？ | chunk_id、source_file、section |
| 合计项和分项是否要一致？ | 制度片段 |
| 找不到依据的问题 | 明确无法确认 |

## 9. 第七步：前端手动验收

MVP 前端至少手动验证：

1. 启动后端。
2. 启动前端。
3. 打开工作台。
4. 上传 `balance_valid.csv`。
5. 上传成功后看到 `report_id`。
6. 后端关闭时，前端显示错误状态。

## 10. 提交前固定命令

后端：

```powershell
pytest
```

前端初始化后：

```powershell
cd frontend
npm test
npm run build
```

如果某条命令不能运行，最终说明里必须写清原因。

## 11. Bug 修复验收模板

修 bug 时按这个格式写：

```text
问题：
复现步骤：
原因：
修复内容：
新增测试：
验收命令：
残余风险：
```

## 12. 常见错误

- 只测成功，不测失败。
- 测试依赖本地私有文件。
- AI 声称测试通过但没有运行。
- 前端只看页面能打开，不验证 API 错误。
- RAG 回答没有检查引用来源。

## 13. 完成标准

- 新增 API 有成功和失败测试。
- 新增规则有通过和失败测试。
- 新增 Tool 能单独测试。
- Agent 流程有样例测试。
- 最终回复说明运行过哪些命令和结果。
