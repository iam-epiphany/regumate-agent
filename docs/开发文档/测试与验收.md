# 测试与验收

ReguMate 当前使用后端 pytest 和前端 TypeScript build 作为基础验收。

## 标准启动验收

评审或演示环境使用 Docker Compose 一键启动：

```powershell
docker compose up --build
```

访问 `http://127.0.0.1:8000`。Qdrant Dashboard 可通过 `http://127.0.0.1:6333/dashboard` 查看。

## 后端测试

运行：

```powershell
.\.venv\Scripts\python.exe -m pytest
```

覆盖场景：

- 健康检查。
- OpenAPI 只暴露当前 RAG 主线接口。
- 上传 txt / md 文档并生成 chunk。
- Markdown 解析生成结构化 block，chunk 继承章节标题。
- chunk 保留章节路径、章节号、父章节号和前后 chunk 指针。
- chunk 保留表格边界，长文本不超过 800 token，并带 overlap。
- 语义断点测试使用 fake embedding，避免测试下载 BGE-M3 模型。
- txt / md / docx / pdf loader 顺序按配置返回，Docling 和 Unstructured 作为可选候选 loader。
- PDF 默认使用 PyMuPDF4LLM loader，loader 评测服务可比较 PDF 候选加载器。
- 上传文档校验 MIME 类型和文件内容签名。
- 空文件返回 400。
- 文档列表和详情。
- 删除文档后列表不再显示该文档。
- Qdrant 向量清理失败时，删除接口返回 503，文档保留为 `delete_failed` 并可重试删除。
- 原始上传文件被外部删除后，列表接口会保留该文档并标记为 `source_missing`，不会自动删除 SQLite 或 Qdrant。
- SQLite 元数据意外丢失但原始 `DOC-*` 文件仍在时，列表接口会尝试从原始文件恢复 document/chunk 记录。
- 上传文档只保存文件、解析并生成 chunk，随后触发后台索引任务。
- 后台索引任务和手动重建接口会调用向量索引服务并校验 Qdrant 向量数量；自动测试使用 fake embedding、fake Qdrant 和 fake vector count。
- API 测试使用临时 SQLite 和临时上传目录，禁止对真实 `data/app.db` 和 `data/documents/originals/` 执行 `drop_all` 或清理操作。
- 索引成功后文档状态为 `indexed`；索引失败后文档状态为 `index_failed` 并保留错误信息。
- 知识库命中时返回回答和引用；自动测试使用 fake retrieval。
- 知识库无依据时拒答。
- 只命中单个泛词的弱相关问题拒答。
- 检索系统不可用时问答接口返回 503。
- `/api/qa/ask/stream` 返回 `text/event-stream`，成功路径包含 `planning`、`retrieval`、`rerank`、`context_selection`、`prompt_build`、`llm_generation` 进度事件和最终 `final` 事件。
- `/api/qa/ask/stream` 检索失败时返回 `error` 事件，不返回误导性的 `final`。
- 复合问题会先由 QueryBudgetPlanner 按问题复杂度动态确定本次 aspect 数；例如包含 8 个处理对象的问题应生成 8 个 aspect，而不是被固定上限截成 5 个。
- 每个 aspect 生成结构化 `semantic_question`、`document_style_statement`、`keyword_anchor` 查询；同一 aspect 内先批量召回、去重和融合，再只调用 1 次 reranker。
- 命中主章节后会补充相关子章节；缺失关键方面时 `retrieval_summary.missing_aspects` 会标记缺口。
- 复合问题的同一 aspect search queries 使用一次批量 embedding 调用；`retrieval_summary` 返回 query、candidate、rerank call、rerank input、rerank output、filter 数量、阶段耗时、`fusion_method`、模型设备和每条 query 的 query type / 召回诊断。
- 上下文片段必须能回溯到 indexed SQLite chunk；不可回溯引用会被过滤，并记录到 `retrieval_summary.citation_validation`。
- 最终入 Prompt 片段按 aspect 覆盖动态选择，不强制凑固定数量；高分但不覆盖当前 aspect 的片段会被 `prompt_filtered_count` 记录并排除。
- 上传和问答写入审计日志；问答日志详情包含问题和回答，不包含引用来源。
- 审计日志接口只返回当天日志，并会将过期日志按天归档到本地 Markdown 文件。
- 历史审计归档支持列表、查看内容和删除。

运行：

```powershell
cd frontend
npm run build
```

验收点：

- TypeScript 编译通过。
- Vite 构建通过。

## 检索质量评测

调参或修改 chunk / embedding / retrieval 逻辑后，先重建索引，再运行：

```powershell
$env:PYTHONIOENCODING='utf-8'
.\.venv\Scripts\python.exe scripts\evaluate_retrieval.py
```

脚本默认读取 `data/test_documents/retrieval_eval_cases.json`，输出 term recall、precision@k、MRR、拒答准确率、p50/p95 延迟，以及后端返回的阶段耗时。该脚本依赖当前 SQLite/Qdrant 中已索引的知识库；如果本地没有相关样例文档，召回指标会偏低，应先上传并索引对应制度样例。

## 文档解析评测

可用本地样本文档观察不同 loader 的解析效果：

```powershell
$env:PYTHONIOENCODING='utf-8'
.\.venv\Scripts\python.exe scripts\evaluate_document_loaders.py data\test_documents\parser_samples
```

关注输出中的：

- `default_loader`：当前生产上传链路会优先使用的 loader。
- `blocks`：结构化片段数量。
- `headings`：标题识别数量。
- `tables`：表格识别数量。
- `pages`：带页码文本覆盖。
- `default block preview`：默认 loader 产出的前几个 block。

`Docling` 和 `Unstructured` 是可选候选 loader；未安装时会显示缺依赖失败，不影响默认解析链路。

## 向量检索手动验收

首次运行前启动 Qdrant：

```powershell
docker compose up -d qdrant
```

安装或更新依赖：

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

如需启用 NVIDIA CUDA 推理：

```powershell
.\scripts\install_cuda_torch.ps1
```

安装后应满足：

```powershell
.\.venv\Scripts\python.exe -c "import torch; print(torch.__version__, torch.cuda.is_available(), torch.cuda.get_device_name(0))"
```

如果数据库中已有旧 chunk，重建向量索引：

```powershell
$env:PYTHONIOENCODING='utf-8'
.\.venv\Scripts\python.exe scripts\rebuild_vector_index.py
```

然后启动后端，上传样例文档，等待文档状态自动变为 `indexed`，再测试：

- 问“总资产怎么计算”，应能召回资产合计相关 chunk。
- 问“火星基地贷款怎么审批”，应返回固定拒答文本。

首次后台构建知识库可能较慢，因为 BGE-M3 和 reranker 模型需要下载或初始化；上传响应本身不应被模型下载阻塞。

## 本轮 RAG 修复验收

新增后端单测覆盖：

- 长中文段落优先按完整句子切分，不从半句话开头。
- 表格解析会提取表头、行列、原始 Markdown 表格、表格标题、页码和章节路径。
- 小表生成表格摘要 chunk + 行级自然语言 table chunk；大表按完整行切分，不跨行合并、不截断行。
- 短前导句紧邻表格时会作为 `table_context` 注入摘要和每条表格行证据，避免“以下情形……”成为孤立 chunk，同时不误作表头。
- docx 表格解析为标准 Markdown 表格，并保留结构化 metadata。
- 文档详情接口返回完整 `text`，`text_preview` 只作为摘要，并标记 `is_truncated`。
- “同一个借款人有多笔贷款时，普惠小微贷款余额应该怎么统计？”应优先命中正文口径 chunk，不让相邻表格背景挤掉直接依据。
- “逾期贷款与风险分类”应生成更完整的监管问答式答案，覆盖逾期统计、逾期天数、两者不能直接等同、10 天示例和长期逾期需重判等证据句。
- “逾期与不良的区别”这类比较问题应能命中自然语言表格行证据，并返回 `table_evidence`，不应因用户没有说“表格”而拒答。
- reranker 高分但问题关键词覆盖不足时拒绝作为可靠证据。
- 问答置信度采用证据强度校准，不再因为 reranker 返回 1.0 就显示 100%。
- 主回答不展示 `DOC-...-CHUNK-...`，该编号只在引用详情中保留。

修复后需重新运行：

```powershell
.\.venv\Scripts\python.exe -m pytest
cd frontend
npm run build
```

## RAG 上下文包验收补充

当前问答接口不再生成半成品自然语言答案，而是输出结构化上下文包。自动测试覆盖：

- `/api/qa/ask` 返回 `answer=null` 和 `context_package`。
- `/api/qa/ask/stream` 通过 SSE 返回运行过程事件，最终 `final` 的 `QAResponse` 与 `/api/qa/ask` 结构一致。
- `/api/qa/retrieve` 直接返回 `LLMContextPackage`。
- `is_final_answer=false`，`mode=rag_context`。
- `context_chunks` 包含引用编号 `[1]`、来源文档、章节、原文片段和元数据。
- `retrieval_summary` 包含 `coverage_notes` 和 `missing_aspects`。
- `retrieval_summary` 包含 `query_plan`、`aspect_retrievals`、`final_prompt_chunk_ids`、`fusion_method`、query/raw candidate/deduped candidate/rerank call/rerank input/rerank output/filter 数量、Prompt 过滤数量、阶段耗时、分数范围、Prompt 选择参数、模型设备和引用回溯校验结果。
- `query_plan.aspects[].search_queries` 为对象数组，包含 `query`、`query_type`、`rationale`；`aspect_retrievals[].diagnostics` 包含每条 query 的原始召回、去重候选、进入重排、重排调用、重排输出和可用命中统计。
- 命中 `3. 资产合计与校验关系` 时，应补充 `3.1 资产合计差异处理`，使 prompt 同时包含差异排查项和外币折算需保留依据。
- 如果同一问题候选中还存在 `4. 逾期贷款与风险分类` 这类无关片段，即使 rerank 分数不低，最终 `context_chunks` 也不应包含它。
- 重复 chunk 会去重，正文开头重复章节标题会清理。
- `llm_prompt` 包含用户问题、检索片段编号和“不得编造知识库中没有的制度依据”等约束。
- `llm_prompt` 不再包含“不能纳入、暂不纳入、需补充材料”等只适用于普惠小微问题的固定要求。
- 输出不再包含“根据知识库引用，可归纳为”或空的“1. 结论”模板。

调优验收样例：

- 模拟复杂问题：`资产合计差异应该优先排查哪些问题？如果差异来自外币折算，需要保留什么依据？`
- 模拟制度：包含 `3. 资产合计差异处理` 和 `4. 外币折算留痕依据`，正文覆盖币种折算、四舍五入、科目映射、重复汇总、汇率日期、折算规则和原币金额来源。
- 修改前基线：query variants 7，原始候选 280，去重候选 40，进入 rerank 40，rerank 输出 20。
- 修改后预期：query variants 7，原始候选 280，去重候选 40，进入 rerank 24，rerank 输出 20；关键 aspect 覆盖仍由既有复合问题 API 测试验证，最终 Prompt 不包含 `4. 逾期贷款与风险分类` 这类明显无关片段。
- 动态 QueryPlanner 回归问题：`系统应如何分别处理普惠小微贷款纳入、绿色信贷识别、逾期与不良贷款关系、资产合计差异排查、外币折算依据保留、历史差错更正记录、多期间影响说明，以及在依据不足时是否可以直接判断银行违规或生成正式监管报告？`。预期至少生成 8 个 aspect，并分别标记检索覆盖和进入 Prompt 覆盖；如果 Prompt 容量不足，应显示容量受限，不能显示为完全覆盖。
- 性能结构预期：5 个 aspect、每个 3 条 search query 的场景，rerank 调用数从 15 次下降到 5 次；8 个 aspect 场景最多 8 次 rerank 调用。
- 问答审计记录 `qa_context_built`，保存问题、`answer=null`、上下文包模式和命中片段数量，不保存完整引用来源。

手动验收问题：

```text
哪些贷款余额可以纳入普惠小微贷款统计，哪些不能？
```

预期：接口返回结构化 `LLMContextPackage`；前端展示 LLM 检索计划、依据片段和折叠的 LLM Prompt Preview，不把 `llm_prompt` 当作最终答案展示。

手动验收复合问题：

```text
资产合计差异应该优先排查哪些问题？如果差异来自外币折算，需要保留什么依据？
```

预期：最终入 Prompt 片段数量通常为 2，`context_chunks` 包含 `3. 资产合计与校验关系` 和 `3.1 资产合计差异处理`；不包含 `4. 逾期贷款与风险分类`；`query_plan` 展示资产合计差异和外币折算留痕两个 aspect，每个 aspect 至少包含语义问题、文档式证据句和关键词锚点 query；`retrieval_summary.fusion_method=aspect_query_rrf_then_bge_rerank`；`llm_prompt` 中出现“币种折算、四舍五入、科目映射和重复汇总”以及“汇率日期、折算规则和原币金额来源”；`is_final_answer=false`，接口不生成最终自然语言答案。

## 检索能力评测脚本

针对《银行业监管制度测试样例_模拟版.pdf》新增专用评测集：

```text
data/test_documents/regulatory_pdf_retrieval_eval_cases.json
```

评测覆盖：

- 简单事实查询：文件版本。
- 字段/术语定义：统计报表定义。
- 条件判断：客户名称包含“小微”是否可直接纳入普惠小微。
- 分类说明：校验规则分类。
- 多条款组合：资产合计差异排查 + 外币折算留痕。
- 表格结构化查询：规则 `R-FX-007`。
- 相似概念：逾期贷款与不良贷款。
- 依据不足：已核销贷款纳入口径、火星基地审批。

运行本地服务后，可通过 API 模式评测：

```powershell
.\.venv\Scripts\python.exe scripts\evaluate_retrieval.py `
  --cases data\test_documents\regulatory_pdf_retrieval_eval_cases.json `
  --api-url http://127.0.0.1:8000/api
```

如需 JSON 报告：

```powershell
.\.venv\Scripts\python.exe scripts\evaluate_retrieval.py `
  --cases data\test_documents\regulatory_pdf_retrieval_eval_cases.json `
  --api-url http://127.0.0.1:8000/api `
  --json
```

当前复测结果摘要：

- 9 个用例全部返回可追溯信息或明确缺失。
- 文件版本、统计报表定义、校验规则分类、规则 `R-FX-007` 均 Top1 命中。
- 资产合计差异 + 外币折算复合问题在 Top5 内同时命中正文主依据。
- “火星基地建设项目如何审批”无依据时 `has_sufficient_context=false`，不再强行召回资产合计类片段。
- `insufficient_writeoff` 命中“当前知识库未提供时应回答无法判断”依据；该场景属于有依据支持拒绝判断，而不是无上下文。
