# 测试与验收

## 开发调试与交付脚本

根目录启动脚本按 Docker 开发热加载和 Docker Compose 全栈部署分工：

- `docker-run.bat` / `docker-run.sh`：开发热加载，后端、前端和 Qdrant 都在 Docker 容器中运行，源码通过 volume 挂载。
- `run.bat` / `run.sh`：全栈部署，使用 Docker Compose 启动 app + Qdrant。
- `rebuild-run.bat`：Windows 显式重建 app 镜像后启动。
- `stop.bat` / `stop.sh`：停止 Docker 开发容器和 Compose 服务。
- `dev-run.bat`：兼容别名，转调 `docker-run.bat`，不再启动本机 Python/Node。

日常开发内循环使用：

```powershell
.\docker-run.bat
```

macOS/Linux 使用：

```sh
sh docker-run.sh
```

该入口启动 Docker app/frontend/Qdrant 容器：后端容器运行 `uvicorn --reload`，前端容器运行 Vite。浏览器访问 `http://127.0.0.1:5174`，代码改动不需要 rebuild。

端口约定：开发热加载默认使用 `REGUMATE_DOCKER_FRONTEND_PORT` 或 `5174` 访问 Vite；全栈部署默认使用 `REGUMATE_APP_PORT` 或 `8000`，由后端容器托管前端静态页面。GPU 不再是启动门禁；无 CUDA 时后端降级 CPU，网页左下角“系统状态”显示降级原因。

新增 Python 依赖、前端 package 依赖、系统包或 Dockerfile 变更时，运行：

```powershell
.\rebuild-run.bat
```

提交前本地检查不再通过根目录 bat 包装，直接运行基础验收命令；交付前先运行本地测试/构建，再运行 `rebuild-run.bat` 验证镜像。

`run.bat`、`docker-run.bat` 和 `rebuild-run.bat` 启动成功时不再输出 `RAG readiness` 文案；脚本仍会读取 `/api/health/rag` 做必要门禁。普通用户通过网页“系统状态”的“问答就绪”查看模型、向量索引、数据库、解析组件和可问答文档数是否满足问答条件；后台预热未完成只提示首次问答可能较慢，不作为未就绪原因。

## 一键自动评测

服务和知识库就绪后，维护者、测试人员或独立评审人员可运行统一入口：

```powershell
# 快速回归：默认 12 道有答案问题 + 6 道无答案问题
.\scripts\run_evaluation.ps1

# 指定快速样本数
.\scripts\run_evaluation.ps1 -Mode Quick -Limit 20

# 全量 300 道有答案问题 + 30 道无答案问题
.\scripts\run_evaluation.ps1 -Mode Full
```

脚本必须先验证 `/api/health/rag.ready=true`、真实可问答文档数大于 0，并检查 QA 工作簿；优先使用 ASCII 暂存文件，暂存目录不存在时复制官方 QA 工作簿到本次运行目录。每次结果写入 `data/evaluation/runs/<时间戳>/`，不得覆盖冻结结果。验收 `evaluation_summary.md` 至少包含 Build ID、真实文档总数/已索引数、答案准确率、来源命中率、引用覆盖率、依据核对通过率、正确拒答率和 P95 延迟；逐题 JSON 保留用于复核。

交付包 contest_dataset 入库与 QA 评测拆分为两个独立入口。

只上传官方 500 个附件并构建知识库：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\upload_contest_knowledge_base.ps1
```

该入口面向测试人员，不要求本机安装 Python。PowerShell 脚本会检查并启动 Docker 服务，先通过 `scripts/warmup_models.ps1` 调用 `/api/health/warmup` 并在终端显示预热进度条，再通过真实 `/api/documents/upload` 逐个上传 `data/contest_dataset/dataset/nfra_page_attachments_500` 的 500 个附件，并轮询文档索引状态。等待索引时按唯一 `document_id` 统计，终端同时显示 `failed`、`missing` 和 `other` 数量；当没有任何排队或索引中的任务时，会输出具体文件名、document_id 和错误信息，避免只显示笼统超时。完成后可以直接进入网页手动提问。

## 当前重点回归

- `.doc/.docx/.pdf/.xls/.xlsx/.jsonl/.csv/.md/.txt` 上传与解析。
- `.doc` LibreOffice 转 `.docx` 后正文和表格解析。
- `.docx` Word OMML 真数学公式解析，覆盖段落顺序、表格单元格、分式、上下标和公式前后变量释义上下文。
- `.pdf` 可提取文本公式候选解析，覆盖页码和上下文窗口；图片/扫描公式不启用 OCR，也不得误报为可计算公式。
- `.xls` LibreOffice 转 `.xlsx` 路径，以及 `xlrd` 兜底路径。
- `.xlsx` 多工作表、合并单元格、多级表头、单位、期间、公式、空行空列解析。
- Excel sheet/table summary chunk、row evidence chunk 和 cell metadata。
- QueryPlanner 对 Excel 取数、比较、计算和 mixed 问题的计划生成。
- 表格结构化检索返回 `sheet_name/cell/unit/value/row_label/column_label`。
- 表格候选不唯一或数值不足时不计算、不补数字。
- Word/PDF 公式计算只在公式可解析、变量值明确、单位一致且运算受支持时返回确定性结果；缺变量、多候选、单位冲突、不支持函数和缺少上下文时返回固定拒答原因码。
- 有界索引队列在内存队列已满时仍持久化任务，并在重启后恢复 `running` 任务。
- 文档列表默认不做全量源文件扫描；显式 `repair_sources=true` 时才执行恢复和缺失标记。
- Windows 路径写入 SQLite、Linux 容器读取时，原文件 basename 仍可正确解析，已误标 `source_missing` 的文档可恢复为 `indexed`。
- 大文档详情接口按 `chunk_offset/chunk_limit` 分页返回，前端不得一次渲染上万片段。
- 问答任务提交前只持久化最小 `pending-receipt`；相同 ID 重复 POST、POST 响应丢失、响应前刷新、短暂断网和服务重启后都应对应同一服务端任务，不重复推理。正常站内切页保留草稿和当前任务；完整刷新不得自动恢复主工作区，只能从问答历史恢复。10 个并发请求不得创建 10 个推理线程。
- 停止生成必须覆盖尚未取得 task ID、`queued`、`running` 和完成竞态：取消请求幂等；`cancelled` 状态可从服务端历史恢复；运行中的迟到答案不得写回；审计日志应记录用户主动停止。
- 文档上传收到 202 后，应覆盖 `parsing/chunking/metadata_indexing/embedding/vector_upsert/verifying` 各阶段崩溃与重启恢复；前端上传字节进度和后端处理阶段不得互相模拟。
- ZIP 条目/解压大小/Excel 逻辑单元格超限、伪造 worksheet dimension、空表和官方最大附件都必须有边界测试；官方 500 份仍需 500/500。
- 删除应注入 Qdrant、文件 unlink 和 SQLite commit 故障，重试后不得出现 SQLite 已索引但当前版本向量缺失。
- 选择题必须覆盖无编号、A/B/C/D、数字序号、①②③④、括号编号和依据不足拒答；无编号时不得生成选项编号，有编号时必须保留原始编号并输出完整选项正文。
- 模型设备必须覆盖 `MODEL_DEVICE=auto/cpu/cuda`、CUDA 不可用降级、CUDA/OOM 异常运行时降级、设备日志和 `/api/health/rag.model_device` 诊断。

## Iterative-100 迭代盲测

系统优化进入反复迭代阶段时，使用 `iterative100` profile 生成每轮全新 100 题：80 道可答题、20 道拒答题。首跑结果作为盲测证据保存；失败题只允许作为回归子集定位通用问题，不能把同一批题反复跑到 90% 后宣称泛化达标。

生成、审计和冻结：

```powershell
$env:PYTHONIOENCODING='utf-8'
python scripts\build_iterative_challenge_100.py --round 1
python scripts\audit_iterative_challenge_100.py --round-dir data\evaluation\iterative_challenge_100\round_1
python scripts\freeze_trust_challenge.py --profile iterative100 --challenge-dir data\evaluation\iterative_challenge_100\round_1
```

首跑盲测和离线评分：

```powershell
$env:PYTHONIOENCODING='utf-8'
python scripts\run_trust_challenge.py `
  --questions data\evaluation\iterative_challenge_100\round_1\questions.jsonl `
  --output outputs\evaluation\iterative_challenge_100\round_1_first_run.json `
  --split all `
  --base-url http://127.0.0.1:8000 `
  --timeout 180

python scripts\evaluate_trust_challenge.py `
  --profile iterative100 `
  --questions data\evaluation\iterative_challenge_100\round_1\questions.jsonl `
  --gold data\evaluation\iterative_challenge_100\round_1\gold.jsonl `
  --results outputs\evaluation\iterative_challenge_100\round_1_first_run.json `
  --report outputs\evaluation\iterative_challenge_100\round_1_first_report.json `
  --lock data\evaluation\iterative_challenge_100\round_1\lock.json `
  --split all
```

`iterative100` 通过条件：`split=all`、题数 100、拒答题 20、总准确率不低于 90%、可答题准确率不低于 90%、拒答准确率不低于 90%，且可答题来源命中、证据 Aspect 完整性、无效引用和禁用结论门禁通过。评分报告会输出 `failure_categories`，用于按检索召回、表格/公式、拒答边界、答案生成或引用完整性等通用根因组织修复。

达标后仍必须用下一批全新 100 题验收；同批失败题回归只能证明修复方向，不作为最终发布结论。

## 来源、版本与多格式专项验收

- metadata 优先级：manifest/人工字段不得被 parser 或文件名推断覆盖，字段来源可审计。
- 传播完整性：Document、文本 chunk、表格 chunk、Qdrant payload 和 Citation 的来源字段一致。
- manifest：JSON/JSONL/CSV 均可读取；SHA 不符、大小不符、歧义匹配和 QA 数据必须失败并给出逐条状态。
- 版本：新文档通过 `supersedes_document_id` 关联旧文档后，旧文档标记为 `superseded`；普通检索不召回失效版本，显式历史查询除外。
- 结构：普通段落中的“第一条/第二条”形成独立 `article_number`，原文不丢失。
