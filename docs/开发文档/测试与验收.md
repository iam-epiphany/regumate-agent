# 测试与验收

ReguMate 当前使用后端 pytest 和前端 TypeScript build 作为基础验收。

## 标准启动验收

评审或演示环境使用 Docker Compose 一键启动：

```powershell
docker compose up --build
```

访问 `http://127.0.0.1:8000`。Qdrant Dashboard 可通过 `http://127.0.0.1:6333/dashboard` 查看。

## 后端测试

运行：

```powershell
.\.venv\Scripts\python.exe -m pytest
```

覆盖场景：

- 健康检查。
- OpenAPI 只暴露当前 RAG 主线接口。
- 上传 txt / md 文档并生成 chunk。
- Markdown 解析生成结构化 block，chunk 继承章节标题。
- chunk 保留表格边界，长文本不超过 800 token，并带 overlap。
- 语义断点测试使用 fake embedding，避免测试下载 BGE-M3 模型。
- txt / md / docx / pdf loader 顺序按配置返回，Docling 和 Unstructured 作为可选候选 loader。
- PDF 默认使用 PyMuPDF4LLM loader，loader 评测服务可比较 PDF 候选加载器。
- 上传文档校验 MIME 类型和文件内容签名。
- 空文件返回 400。
- 文档列表和详情。
- 删除文档后列表不再显示该文档。
- Qdrant 向量清理失败时，删除接口返回 503，文档保留为 `delete_failed` 并可重试删除。
- 原始上传文件被外部删除后，列表接口会同步移除该文档。
- 上传文档只保存文件、解析并生成 chunk，随后触发后台索引任务。
- 后台索引任务和手动重建接口会调用向量索引服务；自动测试使用 fake embedding 和 fake Qdrant。
- 索引成功后文档状态为 `indexed`；索引失败后文档状态为 `index_failed` 并保留错误信息。
- 知识库命中时返回回答和引用；自动测试使用 fake retrieval。
- 知识库无依据时拒答。
- 只命中单个泛词的弱相关问题拒答。
- 检索系统不可用时问答接口返回 503。
- 上传和问答写入审计日志；问答日志详情包含问题和回答，不包含引用来源。
- 审计日志接口只返回当天日志，并会将过期日志按天归档到本地 Markdown 文件。
- 历史审计归档支持列表、查看内容和删除。

## 前端构建

运行：

```powershell
cd frontend
npm run build
```

验收点：

- TypeScript 编译通过。
- Vite 构建通过。
- 构建产物可由 FastAPI 托管。
- 文档删除前出现二次确认，删除请求进行中可取消前端等待。
- 可信问答页面在切换到工作台后再返回时，仍保留之前的问题、回答和引用。
- 审计日志页面展示今日日志和历史归档，历史归档可查看、可删除。

## 文档解析评测

可用本地样本文档观察不同 loader 的解析效果：

```powershell
$env:PYTHONIOENCODING='utf-8'
.\.venv\Scripts\python.exe scripts\evaluate_document_loaders.py data\test_documents\parser_samples
```

关注输出中的：

- `default_loader`：当前生产上传链路会优先使用的 loader。
- `blocks`：结构化片段数量。
- `headings`：标题识别数量。
- `tables`：表格识别数量。
- `pages`：带页码文本覆盖。
- `default block preview`：默认 loader 产出的前几个 block。

`Docling` 和 `Unstructured` 是可选候选 loader；未安装时会显示缺依赖失败，不影响默认解析链路。

## 向量检索手动验收

首次运行前启动 Qdrant：

```powershell
docker compose up -d qdrant
```

安装或更新依赖：

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

如果数据库中已有旧 chunk，重建向量索引：

```powershell
$env:PYTHONIOENCODING='utf-8'
.\.venv\Scripts\python.exe scripts\rebuild_vector_index.py
```

然后启动后端，上传样例文档，等待文档状态自动变为 `indexed`，再测试：

- 问“总资产怎么计算”，应能召回资产合计相关 chunk。
- 问“火星基地贷款怎么审批”，应返回固定拒答文本。

首次后台构建知识库可能较慢，因为 BGE-M3 和 reranker 模型需要下载或初始化；上传响应本身不应被模型下载阻塞。

## 命名检查

排除依赖、构建和缓存目录后，检查旧项目名残留。执行时将 `$pattern` 设置为历史项目名的大小写变体：

```powershell
$pattern = '<old-project-name-pattern>'
$files = Get-ChildItem -Recurse -File | Where-Object { $_.FullName -notmatch '\\(\\.git|\\.venv|node_modules|dist|__pycache__|\\.pytest_cache)\\' }
$files | Select-String -Pattern $pattern
```

## 本轮 RAG 修复验收

新增后端单测覆盖：

- 长中文段落优先按完整句子切分，不从半句话开头。
- 表格按行切分，每一行转换为自然语言 table chunk，不整表原样入库。
- 短前导句紧邻表格时会合并进每条表格行证据，避免“以下情形……”成为孤立 chunk。
- docx 表格解析为标准 Markdown 表格。
- 文档详情接口返回完整 `text`，`text_preview` 只作为摘要，并标记 `is_truncated`。
- “同一个借款人有多笔贷款时，普惠小微贷款余额应该怎么统计？”应优先命中正文口径 chunk，不让相邻表格背景挤掉直接依据。
- reranker 高分但问题关键词覆盖不足时拒绝作为可靠证据。
- 问答置信度采用证据强度校准，不再因为 reranker 返回 1.0 就显示 100%。
- 主回答不展示 `DOC-...-CHUNK-...`，该编号只在引用详情中保留。

修复后需重新运行：

```powershell
.\.venv\Scripts\python.exe -m pytest
cd frontend
npm run build
```
