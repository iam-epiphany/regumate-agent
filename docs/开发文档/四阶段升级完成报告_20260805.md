# ReguMate 四阶段系统升级完成报告（2026-08-05）

## 1. 目标回顾

针对 200 题配对评测准确率卡在 87%（旧 91/100、新 83/100）且存在并发 503、延迟高的问题，
实施了四个阶段升级：检索结构增强 → CRAG 分级路由 → 并发与延迟 → HyDE + 监管文档结构图。

## 2. 各阶段成果

### 阶段一：条款级索引与定义条款定位
- `_definition_clause_support_matches`：定义题（"X是如何定义的"）定位 "X是指/所称X" 条款，
  先扫描已召回文档、全语料回退、跨 chunk 边界后继扩展
- `_retrieval_fit_score`：附件匹配（"内部评级法"↔"权重法"）与章节限定词加分
- 在线验证：D03/D06/D11/T08 全部通过

### 阶段二：CRAG-lite 分级路由
- `_intent_gap_supplement`：问题关键词/引号术语在证据缺失时的文档内词面补搜；
  禁止性问题附加 "{机构}不得" 模式；**兜底条款通道**（"不符合/不满足/无法 + 处理动词"→
  定位 "应纳入…处理/视为…" 条款）
- `_list_completeness_supplement`：列表题（"哪些/包括哪些/哪些情形"）枚举条款补充
- 生成侧：`_align_claim_aspect_ids`（清理 LLM 自由发挥的 aspect_id）、
  `_repair_misaligned_citations`（引用标签错位按词面重叠重定向）、
  extractive 兜底条款选句、evidence_bound 失败后 extractive 兜底
- 在线验证：B2-R09 ✓；B2-R10 从 0/4 拒答 → 4/5 命中 + 0 拒答

### 阶段三：并发 503 修复与延迟优化
- **SQLite 移入 named volume**：Docker Desktop bind mount 上 WAL 的 -wal/-shm sidecar
  无法创建导致偶发 "unable to open database file"（回归 300 题 5-8 个 500）
- 模型获取移出推理锁（lru_cache 串行化冷加载）；锁等待 30→90s 且不消耗请求预算；
  锁超时在预算内重试；API 层瞬态错误重试一次
- 延迟：CPU 上 BGE reranker 每对 ~1.3s（batch 无效），rerank 输入 24→12
  （开放题）→ rerank 17.5s → 8.9s；planner 超时 20→12s；生成 attempts 4→3、预算 90→60s
- **验收：4 workers 并发 40 题 0 错误**（此前 31 个 503）；官方 300 保持 300/300

### 阶段四：HyDE + 监管文档结构图
- `_hyde_supplement_retrieval`：planner 查询全部无果的未覆盖 aspect，LLM 生成假设条款
  补检索（每请求 ≤2 aspect、每 aspect 1 次 LLM 调用、1 次检索）
- `_referenced_clause_chunks`：解析 "本办法第X条" 引用，跨章节定位被引条款（图邻居）
- 在线验证：BW-D12（此前拒答）现给出完整"关键功能"定义；B2-L01（此前 0/5）完整回答业务列表

## 4. 关键根因修复清单

1. **SQLite "unable to open database file"**（回归 5-8/300）：WAL 在 Docker Desktop
   bind mount 上不可靠 → named volume + WAL 容错回退 DELETE + busy_timeout 15s
2. **选择题 500（NameError `_format_prompt_option`）**：`_format_option_evidence_matrix`
   调用不存在的函数名
3. **答案条款被挤出 prompt**：同一 chunk 的多 role 版本去重时保留弱版本
   （`_to_retrieval_results`/`_expand_neighbor_matches` 按 role 优先级保留）+
   同文档模板段落（公共前缀 ≥70%）去重
4. **LLM 引用标签错位**（金标条款 [11] 被引成 [10]）：词面重叠重定向
5. **LLM 自由发挥 aspect_id**：校验前清理不在 required 列表中的标注
6. **并发锁超时**：模型冷加载持锁（锁外获取）、锁等待不消耗预算、90s 等待、预算内重试

## 5. 剩余问题（如实说明）

- 新批次仍有 11 题失败（全部为答案内容质量）：extractive fallback 选句偶发偏离金标句、
  部分语义错位题（如"须设定触发事件的情形"与"触发事件定义"混淆）
- 开放题延迟 p50 ~25s 未达计划 ≤15s 目标：CPU 上 BGE cross-encoder 逐对 1.3s
  （batch 无效），rerank 12 对即 ~10s + LLM 生成 ~12s，硬件下限约 22s；
  需 GPU 或换用更快重排模型才能进一步压缩
- 4 workers 下 LLM 拒答率偏高（并发时 provider 调用竞争）
