# 前端页面开发教程

这个模块带你做 FilingLint Agent 的前端 MVP。第一屏不要做宣传页，而是直接进入工作台，让用户上传报表、查看校验结果、进入异常详情和人工复核。

## 1. 最终要实现什么效果

MVP 前端页面：

```text
/                 工作台，上传报表
/reports/:id      校验结果
/findings/:id     异常详情、证据链、人工复核
/rag              制度问答
/reports/:id/report 审查报告
```

## 2. 推荐技术栈

- React
- TypeScript
- Vite
- fetch 或 axios

不要一开始引入复杂状态管理。MVP 用组件状态和少量 API 封装即可。

## 3. 第一步：初始化前端

如果 `frontend/` 还没有初始化：

```powershell
cd frontend
npm create vite@latest . -- --template react-ts
npm install
npm run dev
```

如果目录非空，先确认里面是否已有 `package.json`，不要覆盖已有文件。

## 5. 第三步：定义 TypeScript 类型

文件：`frontend/src/types/report.ts`

```ts
export interface ReportUploadResponse {
  report_id: string;
  filename: string;
  content_type?: string;
  size: number;
}

export interface RuleResult {
  rule_id: string;
  passed: boolean;
  severity: string;
  message: string;
  expected?: number | string;
  actual?: number | string;
  evidence_refs: string[];

```

字段必须和后端 API 文档保持一致，不要前端自己发明字段。

## 6. 第四步：封装 API client

文件：`frontend/src/api/client.ts`

```ts
export const API_BASE = "http://127.0.0.1:8000";

export async function apiFetch<T>(path: string, options?: RequestInit): Promise<T> {
  const response = await fetch(`${API_BASE}${path}`, options);
  if (!response.ok) {
    throw new Error(`API error: ${response.status}`);
  }
  return response.json() as Promise<T>;
}
```

文件：`frontend/src/api/reports.ts`

```ts
import { API_BASE } from "./client";
import type { ReportUploadResponse } from "../types/report";

export async function uploadReport(file: File): Promise<ReportUploadResponse> {
  const formData = new FormData();
  formData.append("file", file);

  const response = await fetch(`${API_BASE}/reports/upload`, {
    method: "POST",
    body: formData,
  });

  if (!response.ok) {
    throw new Error("上传失败");
  }

  return response.json();
}
```

## 7. 第五步：做上传组件

文件：`frontend/src/components/UploadPanel.tsx`

```tsx
import { useState } from "react";
import { uploadReport } from "../api/reports";

export function UploadPanel() {
  const [message, setMessage] = useState("");

  async function handleChange(event: React.ChangeEvent<HTMLInputElement>) {
    const file = event.target.files?.[0];
    if (!file) return;

    try {
      const result = await uploadReport(file);
      setMessage(`上传成功：${result.report_id}`);
    } catch {
      setMessage("上传失败，请检查文件类型和后端服务");
    }
  }

  return (
    <section>
      <h2>上传监管报表</h2>
      <input type="file" accept=".csv,.xlsx,.xls" onChange={handleChange} />
      {message && <p>{message}</p>}
    </section>
  );
}
```

## 9. 第七步：异常详情页应该展示什么

`FindingDetailPage` 至少展示：

- 异常摘要。
- 规则 ID 和严重程度。
- 期望值、实际值。
- 制度依据片段。
- 根因候选。
- 人工复核表单。

证据链组件接收 `EvidenceChain` 类型，不要直接接收一段大文本。

## 10. 页面状态

每个页面都要考虑：

| 状态 | 怎么展示 |
| --- | --- |
| loading | 显示加载中 |
| empty | 显示还没有数据 |
| error | 显示错误原因和重试入口 |
| success | 显示业务结果 |

## 11. 常见错误

- 前端字段名和后端不一致。
- 页面只有静态 mock，无法调用 API。
- 没有错误状态。
- 把 AI 建议和人工复核结论混在一起。
- 首页做成宣传页，用户不知道怎么上传报表。

## 12. 完成标准

- 前端能启动。
- 工作台能选择文件并调用上传 API。
- 上传成功后展示 report_id。
- 异常详情页设计能承载证据链和复核表单。
- API 类型集中维护，不散落在组件里。
