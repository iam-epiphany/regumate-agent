# 前端页面设计

ReguMate 前端是面向企业日常使用的 RAG 工作台，不做营销首页。

## 页面结构

- `/` 与 `/qa` 均进入可信问答主页面。系统不再设置重复的概览首页，用户进入后可立即提问。
- 左侧导航只保留可信问答、知识库和审计追踪；底部状态区通过 `/api/health/rag` 与完整文档列表计算真实可问答文档数、总数和处理中数量，不允许写死数据规模。
- 知识库 `/documents`：上传文档、查看文档列表、查看索引状态、查看内容片段、删除文档。
- 文档列表每页展示 20 条，支持按可问答、排队中、处理中、处理失败和原文件缺失筛选；失败原因直接显示并保留完整悬浮提示，失败文档可重新加入持久化索引队列。
- 知识库页头只显示真实可问答状态；Qdrant collection、模型与解析器等工程信息不再重复占用主内容区，异常时显示一条可操作的状态说明。
- 内容片段按页加载，每页默认 50 条。片段数很多的 Excel 文档在列表中显示“分页查看”，右侧抽屉展示当前片段范围、总片段数和上一页/下一页，避免打断台账浏览或一次渲染上万条 chunk。
- 可信问答 `/qa`：常驻输入问题、展示当前回答、展示引用来源；旧任务统一从服务端问答历史恢复，不在主页面堆叠。
- 审计日志 `/audit`：查看当天上传、索引、问答记录，并管理历史日志归档。
- 桌面端左侧导航栏固定在视口内，页面内容滚动时导航位置保持不变；移动端恢复为普通顶部区域。

## 交互原则

- 页面文案统一使用 ReguMate 和“可信 RAG 问答”主题。
- 上传入口只接受知识库文档。
- 上传后一键完成，后台自动构建检索索引；列表用“待处理、处理中、可问答、处理失败”等用户语言展示状态。
- 上传区下方固定展示“请选择 .txt、.md、.doc、.docx、.pdf、.xls 或 .xlsx 文档上传”，不展示文档编号、片段数或索引进度等动态小字。
- 上传并入库成功后使用绿色弹窗提示“上传成功”；上传失败使用错误弹窗提示。
- 删除文档前必须二次确认，避免误触。
- 删除请求进行中时，当前行显示“停止等待”；该操作只停止前端等待并刷新列表，不宣称取消后端已开始的删除。
- 删除成功后使用绿色弹窗提示“删除成功”，立即刷新列表并清空 chunk 预览；若后端返回 `delete_failed`，文档保留在列表中并允许重试删除。
- 问答页必须同时展示回答状态和引用来源。
- 问答答案正文保留可点击的 `[1]`、`[2]` 引用按钮并联动证据卡。页面只提供一个“复制回答”按钮，默认复制去除引用编号后的正文。
- 问答页不展示示例问题；历史问题从服务端最近任务读取，可在抽屉中恢复，保留复制答案和重新生成。普通模式只展示业务进度，勾选“展示技术详情”后才请求并显示 Prompt、QueryPlanner 和复杂诊断。
- 问答页面向真实用户时不要求填写 A-D 选项；用户可直接把选项粘贴在问题框内，后端会预处理并抽取 2–8 个内嵌选项，支持 A/B/C、1/2/3、①②③、换行、多空格、竖线，以及从表格中复制后用制表符分隔的选项组。只有用户问题本身是“下列哪项/哪组选项”这类选择题且没有可识别选项时，后端才返回澄清提示，引导用户补充选项或改成普通问法。
- 问答页使用后端持久化问答任务作为状态源。`draftQuestion` 与当前任务只保存在顶层 React Provider 内存中，因此站内页面切换保留草稿、当前问题和处理进度；浏览器完整刷新后主工作区为空，后台任务继续执行并可从服务端问答历史恢复。前端仅在 POST 响应尚未确认时把 `client_request_id/question/include_debug` 作为 `pending-receipt` 写入 `localStorage`，取得 task ID 后立即删除；响应丢失时使用同一 ID 静默幂等补交，但不把任务恢复到刷新后的主工作区。
- 问答页不把 reranker 分数解释为概率；统一称为“证据强度”，拒答时展示依据不足。
- 问答页在回答前展示“处理进度”；活动任务优先订阅持久化任务 SSE，断线时回退任务快照轮询，显示理解问题、查找相关依据、筛选最相关依据、组织可信回答、核对答案与依据，技术模式再补充工程阶段。`/api/qa/ask/stream` 保留为兼容接口，但页面恢复以持久化任务接口为准。
- 进度状态必须区分等待处理、正在处理、已完成、已跳过和处理失败；只显示后端任务快照中真实报告的事件。没有事件的阶段显示“未报告”，不得从最终结果合成 `completed/skipped`。拒答、可信回答、降级回答和执行失败使用不同视觉状态；`grounding_validation.passed=false` 绝不显示绿色可信成功。
- 引用来源作为“证据案卷”展示文件、章节/页码、证据角色和最小必要摘录；支持展开完整片段，`chunk_id`、分数等工程字段折叠在“技术信息”中。
- 审计日志页展示“提问、文档上传、文档已入库”等中文动作，不直接展示 `qa_answered`、`document_indexed` 等内部事件码。
- 审计日志“详情”中的问答事件必须展示问题、回答、状态、拒答原因和引用数量；遇到较长的问题或回答时，保留开头与结尾并在中间用“……”省略；点击该段文本可展开查看完整内容，再次点击可收起，结构化 JSON 放入折叠的技术详情。
- 审计日志页只展示当天日志；历史日志按天显示为归档文件，用户可查看某天归档的日志摘要和日志表格，也可删除该天归档文件。
- 问答输入框在空白、处理中、回答完成、拒答、失败和取消状态始终存在。处理中锁定文本框与技术详情设置，原提交按钮切换为“停止生成”；任务完成或停止后立即恢复“开始问答”，不支持并行排队下一问。
- 知识库页查看内容片段时按页显示完整文本，不只显示预览；正文保留段落换行，表格行显示为自然语言证据。
- Excel 表格 chunk 在正文前展示工作表、表名、单位、期间、行标签和单元格摘要；引用列表和 RAG 上下文片段展示工作表、单元格、单位、原始值、行标签和列标签。
- 内容片段卡片头部已显示章节名时，正文区域不重复展示同一个章节标题；表格行证据和普通正文使用一致字号。
- 避免在普通用户界面暴露 `chunk`、`tokens`、`indexed`、`rerank`、`Qdrant`、`SQLite` 等工程术语；需要追溯时放入低干扰的详情区。
- 无数据时给出清晰空状态。
- 前端不展示当前阶段未实现的旧业务入口。

## API 调用

- `src/api/documents.ts`：文档上传、列表、详情、删除。
- `src/api/qa.ts`：可信问答、问答任务创建与状态查询。
- `src/api/audit.ts`：审计日志。
- `src/api/system.ts`：健康检查。

## v4 页面调整

- 工作台删除“最近操作”模块，避免与审计日志重复；工作台只展示系统就绪状态、知识库规模、索引队列、依赖状态、快捷入口和待处理异常摘要。
- 审计日志页统一展示系统事件流，支持 `info/warning/error` 级别筛选，显示首次发生时间、最近发生时间、累计次数和用户友好的中文描述；技术详情默认折叠。
- 重复异常不在前端连续刷屏。同一源文件缺失、索引失败或依赖异常短时间多次出现时，页面展示一条聚合事件和累计次数。
- 问答页对 Excel 拒答展示可解释原因：未检索到有效单元格、指定期间不存在、指定指标不存在、候选不唯一、单位不一致、空值或除零等；普通模式只展示结论和依据，调试模式才展示 QueryPlanner、match_status 和完整诊断。
- 知识库详情继续使用分页加载 chunk，避免 395 这类上万片段 Excel 文档一次渲染导致浏览器卡死。
- 视觉风格保持轻量 React/Vite/lucide，不引入重型 UI 框架；重点强化银行监管场景的专业层级、状态徽标、引用卡片和表格证据展示。
## 可信答案展示补充

`/qa` 页面主标题为“可信监管问答”，优先展示最终答案、证据强度、拒答原因和降级状态；引用与答案分离，复杂检索诊断折叠展示。

页面展示分为两块：

- 最终答案：展示回答或明确拒答。表格引用展示文件、sheet、坐标、值、单位和计算公式；制度引用展示章节、条款和最小必要原文。
- 依据片段：调试模式展示 `context_package.context_chunks`，包含引用编号、来源文档、章节、原文片段和折叠的工程信息。
- 检索观测：完整展示 QueryPlanner 的 aspect、`evidence_need`、结构化 search query、query type、召回状态、最终上下文和 Prompt Preview。

页面不再使用 `localStorage` 保存最近一次 `task_id`、草稿、当前问题或答案。它只保存未确认 POST 的最小 `pending-receipt`；任务、进度、答案和历史始终以服务端任务快照为准。状态徽标继续使用“依据较充分/依据一般/依据较弱/依据不足”这类用户可理解文案，不直接暴露 reranker 百分比。

检索观测区域直接展示 LLM 检索计划，便于开发和验收：

- 运行过程时间线：普通模式展示理解问题、检索相关依据、重排候选片段、生成回答、问答处理；技术模式额外展示上下文精选、Prompt 构造和事实校验。运行中显示轻量加载图标，完成显示对勾，跳过显示“已跳过”，失败显示错误图标。
- LLM 检索计划：展示 QueryPlanner 拆出的 aspect 子问题、证据需求、关键词，以及 `semantic_question`、`document_style_statement`、`keyword_anchor`、`table_locator` 等 query 和 rationale。
- Aspect 召回状态：展示每个 aspect 是否已检索到依据、是否进入最终 Prompt、每条 query 的原始召回/去重候选/进入重排/重排调用/重排输出/可用数量、候选 chunk、融合分和最终入 Prompt 状态；缺失时提示未找到足够依据。
- 最终上下文：分别展示原问题方面数、检索覆盖数、进入 Prompt 的方面数和是否受 `MAX_PROMPT_CHUNKS` 容量限制，例如 `检索 8/8，入 Prompt 5/8（容量受限）`。

调试详情仍折叠展示，包含 query variants、候选与过滤数量、模型设备、分数范围、阶段耗时、最终 chunk id、融合方法和完整 `llm_prompt`。普通用户模式不返回这些字段。

## v5 系统性前端优化

- 全局设计语言调整为低饱和冷灰、深蓝灰、稳重蓝和少量案卷式琥珀色，避免营销页、大屏、玻璃拟态和大面积渐变。页面通过边框、左轨、分隔线和表格密度组织信息，不依赖悬浮卡片堆叠。
- `App` 外层使用 `QATaskProvider`，问答任务状态不再绑定到 `/qa` 页面组件生命周期。Provider 分离输入草稿和已提交问题，站内路由切换不会清空；完整刷新则重新建立空工作区。`localStorage` 只保留尚未取得 task ID 的最小提交回执，任务状态、进度、答案和历史始终从后端快照恢复。轮询采用 1/2/4/8/10 秒退避并支持重连。
- 默认入口调整为可信问答，移除独立概览首页，避免进入系统后再次选择主功能。运行状态收敛到全局侧栏，技术依赖只在异常说明或折叠详情中出现。
- 工作台核心能力区只展示已经接入或已启用的能力：监管制度依据检索、统计报表知识问答、答案引用与来源追溯、依据不足自动拒答、选择题完整解释和问答过程审计记录，不制造虚假的可信度百分比。
- 可信问答页重构为结论优先的 8:4 案卷布局：左侧回答文档，右侧固定“证据案卷”；提问框和运行中进度占据完整主宽度，窄屏自动切换为单栏。
- 回答正文保留 `[1]`、`[2]` 等可点击引用按钮。点击正文引用会定位并高亮右侧对应证据；点击证据编号也会保持高亮，降低答案和依据之间的核对成本。“复制回答”默认复制不含行内引用编号的正文。
- 拒答在问答页显示为可信业务结果，而不是系统失败。界面展示拒答原因、已知依据状态、缺少的关键依据或用户可补充材料；`generation_status=skipped` 时进度明确显示“已跳过”，最终处理显示完成。
- 技术详情继续保留 QueryPlanner、上下文片段、Prompt 和运行指标，但默认折叠；普通用户视图优先展示最终结论、依据状态和来源。
- 知识库页重构为“文档台账”。页面头部展示知识库是否可支撑问答，支持文件名/编号搜索和状态筛选；内容片段改在右侧抽屉分页查看。内部错误码默认不直接暴露，用户先看到中文原因，原始错误码放入技术详情。
- 审计日志页重构为“审计追踪”。移除重复的四项统计卡，由页头风险状态和日志表格直接表达重点；表格字段为时间、操作类型、操作对象、执行结果、出现次数和说明，原始 JSON 继续折叠在技术详情中。
- 所有核心页面补充更明确的加载、空状态、失败说明和重试入口。动画仅用于加载和状态变化，并继续支持 `prefers-reduced-motion`。
- 知识库页初始加载、健康检查和处理快照均有错误/重试状态；上传期间互斥，collection 名从 health 获取。文档处理进度由 XHR 上传字节与后端阶段两段组成。
- 工作台依赖加载失败不得伪装为空数据；Office 就绪口径与后端保持一致。详情弹窗支持焦点锁定、Esc 关闭；文档台账在 375/768/1440 px 下切换为可读的移动卡片或桌面表格。

## v6 可信工作台落地规范

- 视觉基色为监管深蓝 `#173B52`、证据琥珀 `#8A6A2F` 和冷灰背景 `#F3F6F8`。界面不使用大面积蓝紫渐变、玻璃拟态、发光和无意义动态数字。
- 全局状态由 `SystemStatusProvider` 统一读取真实健康接口和文档列表，每 30 秒刷新；侧栏、提问范围和就绪判断共享同一来源。
- 提问框支持长文本自动增高和 `Ctrl/Cmd + Enter` 提交，明确展示当前知识范围、文档规模和是否启用技术详情。
- 主操作是 46×46px 圆形纯图标按钮：空闲时为深蓝色纸飞机发送图标，运行时原位切换为错误色停止方块，取消中显示 spinner。按钮正文不出现中文，但必须保留 `aria-label`、`title`、键盘焦点和 `Ctrl/Cmd + Enter`。取消调用持久化任务接口；成功后页面显示“已停止生成”，历史任务标记为“已停止”。
- 回答先显示结论，再显示选择题选项解释、表格取数或计算结果、拒答原因和补充材料建议。`grounding_validation` 未提供时显示“未提供核对结果”，不得假定通过。
- 答案与证据使用独立视觉容器。证据列表采用单一编号体系，避免浏览器列表编号与引用编号重复；制度原文使用适合长文阅读的本地宋体栈，坐标与公式使用等宽字体。
- 选择题不仅显示选项编号，必须同时显示选项正文、判断结果和引用依据。拒答被视为可信业务结果，不使用 `refusal`、`skipped` 等内部状态作为面向用户的最终文案。
- 动画仅用于加载、当前阶段和抽屉进入，且遵循 `prefers-reduced-motion`。圆角、间距、按钮、状态色统一由 `styles.css` 根变量控制。

## v7 常驻问答工作区

- 删除结果态的“提出新问题”按钮。主页面始终按“当前问题 → 处理进度 → 答案与证据 → 输入框”组织，一次只展示一个前台任务；每次提问仍是独立、可审计的 RAG 任务，不继承上一问语义。
- 输入框桌面端位于页面底部 sticky 区域，移动端回到普通文档流，避免软键盘遮挡。初始高度为 52 px，随内容增长到 240 px，超过后仅输入框内部滚动；保留 `Ctrl/Cmd + Enter` 提交。
- 空闲且有草稿时显示“开始问答”；知识库未就绪或草稿为空时禁用。`queued/running` 状态原位切换为错误色“停止生成”，取消请求处理中显示“正在停止”。

### 已核验流式预览与系统状态

- 首个可信 claim 到达后，在处理进度下显示“逐句已核验 / 正在生成可信回答”。正文按完整 claim 增长，行内引用可立即联动右侧证据案卷；最终快照沿用相同文档框架接管，禁止前端模拟打字。
- 处理进度完成节点使用 36px 浅绿色实底容器，绿色 `CheckCircle2` 固定 20px 并用 `place-items:center`、`display:block` 严格居中；桌面连接线位于图标下层，860px 以下单列并隐藏连线。
