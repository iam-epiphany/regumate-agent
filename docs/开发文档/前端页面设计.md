# 前端页面设计

ReguMate 前端是面向学习和演示的 RAG 工作台，不做营销首页。

## 页面结构

- 工作台 `/`：后端状态、知识库概览、最近操作、主功能入口。
- 工作台后端连接状态跟随“银行监管可信问答工作台”标题显示，不单独占用一行。
- 知识库 `/documents`：上传文档、查看文档列表、查看索引状态、查看内容片段、删除文档。
- 可信问答 `/qa`：输入问题、展示回答、展示引用来源。
- 审计日志 `/audit`：查看当天上传、索引、问答记录，并管理历史日志归档。
- 桌面端左侧导航栏固定在视口内，页面内容滚动时导航位置保持不变；移动端恢复为普通顶部区域。

## 交互原则

- 页面文案统一使用 ReguMate 和“可信 RAG 问答”主题。
- 上传入口只接受知识库文档。
- 上传后一键完成，后台自动构建检索索引；列表用“待处理、处理中、可问答、处理失败”等用户语言展示状态。
- 上传区下方固定展示“请选择 .txt、.md、.docx 或 .pdf 文档上传”，不展示文档编号、片段数或索引进度等动态小字。
- 上传并入库成功后使用绿色弹窗提示“上传成功”；上传失败使用错误弹窗提示。
- 删除文档前必须二次确认，避免误触。
- 删除请求进行中时，当前行显示“取消删除”；取消会中止前端等待并刷新列表。
- 删除成功后使用绿色弹窗提示“删除成功”，立即刷新列表并清空 chunk 预览；若后端返回 `delete_failed`，文档保留在列表中并允许重试删除。
- 问答页必须同时展示回答状态和引用来源。
- 问答页使用当前浏览器标签页的 `sessionStorage` 保留最近一次问题、回答、引用和提示；用户切到工作台再返回可信问答时，界面仍显示之前的问答结果。
- 问答页不直接展示 reranker 百分比；命中时展示“依据较充分/依据一般/依据较弱”，拒答时展示依据不足。
- 问答页在依据片段前展示“检索观测”区域；查询运行中通过 `/api/qa/ask/stream` 实时显示问题理解、依据检索、候选重排、上下文精选和 Prompt 构造状态。
- “检索观测”的阶段状态使用紧凑单行展示，格式为“阶段标题：阶段说明”，减少占用高度并使用较小字号。
- 引用来源默认展示文件、章节和摘录；`chunk_id` 等追溯编号折叠在“查看来源信息”中。
- 工作台“最近操作”和审计日志页展示“提问、文档上传、文档已入库”等中文动作，不直接展示 `qa_answered`、`document_indexed` 等内部事件码。
- 工作台“最近操作”和审计日志“详情”遇到较长的问题或回答时，保留开头与结尾并在中间用“……”省略；点击该段文本可展开查看完整内容，再次点击可收起。
- 审计日志页只展示当天日志；历史日志按天显示为归档文件，用户可查看某天归档的日志摘要和日志表格，也可删除该天归档文件。
- 问答请求进行中时，查询按钮置灰禁用，并显示“查询中”，避免重复提交。
- 知识库页查看内容片段时显示完整文本，不只显示预览；正文保留段落换行，表格行显示为自然语言证据。
- 内容片段卡片头部已显示章节名时，正文区域不重复展示同一个章节标题；表格行证据和普通正文使用一致字号。
- 避免在普通用户界面暴露 `chunk`、`tokens`、`indexed`、`rerank`、`Qdrant`、`SQLite` 等工程术语；需要追溯时放入低干扰的详情区。
- 无数据时给出清晰空状态。
- 前端不展示当前阶段未实现的旧业务入口。

## API 调用

- `src/api/documents.ts`：文档上传、列表、详情、删除。
- `src/api/qa.ts`：可信问答。
- `src/api/audit.ts`：审计日志。
- `src/api/system.ts`：健康检查。

## 验收

运行：

```powershell
cd frontend
npm run build
```

构建通过即为当前前端基础验收。
## RAG 上下文展示补充

当前 `/qa` 页面不再把检索结果包装成最终回答展示。页面主标题调整为“可信 RAG 上下文”，普通模式展示提示语：“当前系统已检索到以下相关依据，后续接入 LLM 后将基于这些片段生成回答。”

页面展示分为两块：

- 依据片段：展示 `context_package.context_chunks`，即后端真正传给 LLM Prompt 的片段，包含引用编号、来源文档、得分、章节、原文片段和折叠的 `chunk_id`。
- 检索观测：完整展示 QueryPlanner 的 aspect、`evidence_need`、结构化 search query、query type、召回状态、最终上下文和 Prompt Preview。

页面仍使用 `sessionStorage` 保存最近一次问题和上下文包响应；状态徽标继续使用“依据较充分/依据一般/依据较弱/依据不足”这类用户可理解文案，不直接暴露 reranker 百分比。

检索观测区域直接展示 LLM 检索计划，便于开发和验收：

- 运行过程时间线：正在理解问题、正在检索相关依据、正在重排候选片段、正在精选最终上下文、正在构造 LLM Prompt。运行中显示旋转图标，完成显示对勾，失败显示错误图标。
- LLM 检索计划：展示 QueryPlanner 拆出的 aspect 子问题、证据需求、关键词，以及 `semantic_question`、`document_style_statement`、`keyword_anchor` 三类 query 和 rationale。
- Aspect 召回状态：展示每个 aspect 是否已召回依据、每条 query 的候选/重排/可用数量、候选 chunk、融合分和最终入 Prompt 状态；缺失时提示未找到足够依据。
- 最终上下文：展示已使用片段数和 aspect 覆盖比例，例如 `2/5`、`2/2 个问题方面已覆盖`。

调试详情仍折叠展示，包含 query variants、候选数、rerank 数、过滤数、vector/rerank 分数范围、原始阶段耗时、最终进入 Prompt 的 chunk id、融合方法和完整 `llm_prompt`。当前 RAG-only 阶段不展示最终答案 LLM 原始输出，只显示“当前阶段未接入”。
