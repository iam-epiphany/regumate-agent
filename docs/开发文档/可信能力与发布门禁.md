# 可信能力与发布门禁

## 当前实现边界

本轮保留稳定的分块、Embedding、Reranker、SpreadsheetCell 与表格索引主线，只补充来源文件可追溯、召回前过滤、mixed/scenario、监管语义 Grounding 和发布复现能力。

官方已确认本赛题交付不要求文件 URL。比赛数据包、入库文件名、SHA、文档标题、chunk/页码和 Excel 单元格是来源命中的核心依据；`source_url/attachment_url` 仅为可空兼容字段，缺失时不影响入库、检索、引用或发布。package manifest 用于证明文件清单、去重和本地 custody，不再替代或补充官网 URL 核验。

60 题挑战集已经建立结构和类别配额，但目前全部为 `needs_review`。其 accepted document/chunk/cell、预期语义 frame 和禁止结论必须由人工依据真实语料逐题确认。评测器和 release gate 会拒绝未复核数据。

## 工具入口

- `scripts/build_package_manifest.py`：生成比赛数据包文件清单、SHA、大小和原始文件名。
- `scripts/audit_official_metadata.py`：审计 Document、Chunk 和 Qdrant payload 的文件级 metadata 一致性；URL 为空不是失败条件。
- `scripts/audit_evaluation_isolation.py`：按文件名和 SHA 证明 QA/gold 未被生产知识库摄入。
- `scripts/evaluate_trust_challenge.py`：按 Aspect、语义、拒答和禁止结论评分。
- `scripts/build_release_manifest.py`：绑定 Build ID、Git commit、源码树 SHA、Docker digest 和产物 SHA。
- `scripts/run_release_validation.ps1`：失败即停、保留 checkpoint 的一键正式验收入口。

## 不可绕过的复核步骤

1. 逐题复核 60 题挑战集并填写可接受文档、Chunk、单元格与预期 frame。
2. 在冻结 commit 上执行 GPU、CPU 全量评测；正式报告只引用该 release manifest 对应结果。
