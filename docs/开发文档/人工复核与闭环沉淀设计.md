# 人工复核与闭环沉淀开发教程

这个模块带你把 AI 发现的异常交给人确认，并把确认后的异常沉淀为历史案例。人工复核是监管报送场景里非常重要的一环：AI 可以建议，但不能替代最终判断。

## 1. 最终要实现什么效果

异常详情页上，人工可以选择：

- 确认异常。
- 驳回异常。
- 需要补充材料。

提交后保存复核记录，并可选择沉淀为历史案例。

## 3. 第一步：定义复核状态

建议状态：

```text
pending -> confirmed
pending -> rejected
pending -> needs_more_info
confirmed -> archived
```

含义：

| 状态 | 含义 |
| --- | --- |
| `pending` | 待人工复核 |
| `confirmed` | 确认异常成立 |
| `rejected` | 异常不成立 |
| `needs_more_info` | 需要补充材料 |
| `archived` | 已沉淀为历史案例 |

## 4. 第二步：定义复核 schema

文件：`backend/app/schemas/review.py`

```python
from pydantic import BaseModel


class ReviewCreate(BaseModel):
    finding_id: str
    decision: str
    comment: str
    reviewer: str = "demo_user"


class ReviewRecord(BaseModel):
    review_id: str
    finding_id: str
    decision: str
    comment: str
    reviewer: str
    reviewed_at: str
```

## 5. 第三步：写保存复核记录的 service

第一阶段可以先用本地 JSON 文件模拟存储。

文件：`backend/app/services/review_service.py`

```python
import json
from datetime import datetime, timezone
from pathlib import Path
from uuid import uuid4

from backend.app.schemas.review import ReviewCreate, ReviewRecord

REVIEW_FILE = Path("data/cases/reviews.json")


def create_review(payload: ReviewCreate) -> ReviewRecord:
    REVIEW_FILE.parent.mkdir(parents=True, exist_ok=True)
    record = ReviewRecord(
        review_id=str(uuid4()),
        finding_id=payload.finding_id,
        decision=payload.decision,
        comment=payload.comment,
        reviewer=payload.reviewer,
        reviewed_at=datetime.now(timezone.utc).isoformat(),
    )

    records = []
    if REVIEW_FILE.exists():
        records = json.loads(REVIEW_FILE.read_text(encoding="utf-8"))
    records.append(record.model_dump())
    REVIEW_FILE.write_text(json.dumps(records, ensure_ascii=False, indent=2), encoding="utf-8")
    return record
```

## 6. 第四步：写复核 API

文件：`backend/app/api/reviews.py`

```python
from fastapi import APIRouter

from backend.app.schemas.review import ReviewCreate, ReviewRecord
from backend.app.services.review_service import create_review

router = APIRouter()


@router.post("", response_model=ReviewRecord)
def submit_review(payload: ReviewCreate):
    return create_review(payload)
```

在 `main.py` 中挂载：

```python
from backend.app.api import reviews

app.include_router(reviews.router, prefix="/reviews", tags=["reviews"])
```

## 7. 第五步：沉淀历史案例

当 `decision = confirmed` 时，可以把异常沉淀为案例。

历史案例结构：

```json
{
  "case_id": "CASE_001",
  "finding_id": "FINDING_001",
  "finding": "资产合计与分项加总不一致",
  "root_cause": "模板公式漏计债券类资产",
  "review_comment": "确认异常成立",
  "evidence_refs": ["RULE:RPT_BALANCE_001", "REG:reporting_rules_sample#2.1#001"]
}
```

第一阶段可以手动生成案例文件，后续再做自动归档 API。

## 8. 第六步：写测试

```python
from backend.app.schemas.review import ReviewCreate
from backend.app.services.review_service import create_review


def test_create_review():
    record = create_review(
        ReviewCreate(
            finding_id="FINDING_001",
            decision="confirmed",
            comment="确认异常成立",
        )
    )
    assert record.finding_id == "FINDING_001"
    assert record.decision == "confirmed"
```

## 9. 前端页面怎么做

异常详情页底部放复核表单：

- 单选：确认 / 驳回 / 需要补充材料。
- 文本框：复核意见。
- 按钮：提交复核。
- 提交后展示复核记录，区分 AI 建议和人工结论。

## 10. 常见错误

- 用 AI 结果覆盖人工结论。
- 复核意见只是备注，没有结构化 decision。
- 确认异常后没有沉淀案例。
- 案例没有 evidence refs。

## 11. 完成标准

- 可以提交复核记录。
- 复核记录包含 finding_id、decision、comment、reviewer、reviewed_at。
- 人工结论和 AI 建议分开保存。
- confirmed 异常可以沉淀为历史案例。
