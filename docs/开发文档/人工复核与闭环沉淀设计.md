# 人工复核与闭环沉淀设计

当前 RAG-only 阶段暂不实现人工复核、异常闭环、历史案例沉淀。本文档保留为未来扩展说明，避免代码和文档继续引用已删除的 review/finding 主线。

## 1. 当前阶段做什么

当前只记录两类运行痕迹：

- `qa_logs`：保存用户问题、系统回答、是否拒答、置信度。
- `audit_logs`：保存文档上传、文档入库、问答、拒答等操作。

这些记录用于审计和演示，不等同于人工复核。

## 2. 当前阶段不做什么

- 不提供 `/api/reviews`。
- 不提供人工复核表单。
- 不保存 finding 复核结论。
- 不生成历史异常案例。
- 不生成审查报告。

## 3. 未来扩展方向

如果后续重新开发报表检查或异常排查，可以再新增：

- 复核队列。
- 复核结论 schema。
- 历史案例表。
- 审查报告生成。
- 相似案例检索。

但必须先保证异常来源、规则结果、制度引用都已经结构化，否则人工闭环没有可信基础。

## 4. 验收标准

- 当前前端不出现人工复核入口。
- 当前后端不包含 `/api/reviews`。
- 审计日志只展示 RAG 问答与文档入库相关操作。
