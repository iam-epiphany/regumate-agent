# ReguMate 系统升级计划（检索层重构路线图）

> 依据：200 题联合评测（174/200 = 87%）与 RAGAS 分层归因结论——正确率天花板在**检索层证据召回**（条款错位/跨文档不全），生成与校验层已成熟（表格 20/20、拒答 39/40）。本计划以检索层为核心，四阶段推进，每阶段独立验收、可回滚。

## 0. 总体目标与验收标准

| 指标 | 当前 | 目标 |
|---|---|---|
| 200 题正确率（旧91+新83） | 174/200（87%） | **≥ 184/200（92%）** |
| 官方 300 题回归 | 300/300 | 保持 300/300（每阶段必跑） |
| 单题延迟（串行） | 平均 30.8s / 最大 125.7s | 平均 ≤ 15s / 最大 ≤ 60s |
| 并发稳定性 | 4 并发 31 个 503 | 4 并发 0 错误 |
| 后端单测 | 567 passed | 全绿 + 新增测试覆盖新通道 |

每阶段完成后：后端单测 → 官方 300 回归 → 200 题配对回归（回归输出另存，首跑不可变）→ 性能采样。

## 阶段一：检索结构性增强（预计 +6~10 题，优先实施）

**目标**：解决"定义条款错位"（D03/D06/D11/T02/T08/R01 类）——证据在语料里，但没被检索到正确条款。

### 1.1 条款级索引与定义条款定位
- **现状**：chunk 按固定长度切分，定义句（"所称X是指…"）可能被切碎或排在 top-k 之外；`section_number`/`parent_section_number` 元数据已存在但未用于检索。
- **方案**：
  - 利用 `第X条`/章节标题正则 + 现有 section 元数据，构建内存级"文档 → 条款号 → chunk"映射（文档数 500，chunk 4.6 万，内存可控，或入库为 `document_clause_index` 表）
  - 定义型问题识别（问题含引号术语 + "定义/如何界定/是什么/指什么"），新增**定义条款通道**：对引号术语执行 `所称{术语}|{术语}是指|{术语}指` 的精确/词面检索，命中条款 chunk 强制进入 prompt（覆盖现有 aspect 选择）
  - 同文档条款扩展：定义条款的前后邻接 chunk（复用 next/previous_chunk_id）一并进 prompt，保证"定义 + 适用范围"完整
- **验证**：D03（473 第四条）、D11（482 操作风险条款）、B2-D06（402 专业贷款条款）三类样本通过；官方 300 回归无退化。

### 1.2 附件/同概念文档消歧
- **现状**：D06 命中 417（信息披露附件）而非 402（内部评级法风险暴露分类）；问"内部评级法"检索到"权重法"附件。
- **方案**：
  - 问题限定词 → 附件/文档类型映射（通用词表："内部评级法"→附件 4/5/6；"权重法"→附件 2/3；"标准法"→附件 14；"第三档"→附件 23；"偿付能力监管规则第N号"→编号直连），注入检索 query 与元数据过滤
  - 多候选跨文档时，按"文档标题 × 问题限定词"词面匹配度重排（升级 `_evidence_fit_bonus` 为检索 query 级加权，而不只是 prompt 选择级）
- **验证**：D06/X04 样本通过；构造"权重法 vs 内部评级法"对抗样本确保不误伤。

### 1.3 同文档段落消歧（T08 类）
- **现状**：问"财产保险公司压力情景"，命中同文档"人身保险公司"段落。
- **方案**：chunk 的小节标题（section_title/section_path）与问题机构/业务限定词（财产保险公司/人身保险公司/非寿险/寿险…）匹配加权；同文档内多段候选按小节标题优先级重排。
- **验证**：T08 样本；"恢复计划示例（商业银行版 vs 保险公司版）"对抗样本。

**阶段一验收**：200 题 ≥ 181（90.5%）；无官方 300 退化；延迟不劣化（新增通道为精确检索，开销 < 200ms）。

## 阶段二：CRAG 式分级路由（预计 +4~6 题）

**目标**：解决"证据在手但答错/答不全"（R01 答错条款、L 组列表漏项、跨文档只取一份）。

### 2.1 生成前证据-问题相关性预判
- **现状**：`required_aspect_ids` 覆盖预检已存在，但只拦"完全无证据"；"检索到错误条款"（R01：问禁止性规定、证据是监管指标）直接进入生成。
- **方案**（CRAG 思想）：
  - 确定性预判：问题核心词（引号术语/限定词）与候选证据的条款标题、正文的命中度评分
  - 三级路由：**正确**（命中度高）→ 生成；**模糊**（部分命中）→ 补一轮定向检索（条款扩展/第二文档/换限定词）；**错误**（命中度极低但检索非空）→ 丢弃候选重新检索
  - 补检索与生成共享总预算（当前 evidence_bound 独立 90s 预算是 503 诱因之一，一并收敛）
- **验证**：R01/X01（跨文档第二份文档补检索）样本；列表题 L01/L06 强制"逐条列出 + 每条对应证据"。

### 2.2 列表完整性强化
- **方案**：列表型问题（"包括哪些/哪几种/哪些情形"）的 prompt 增加"必须逐项列出、每项标注引用、不得合并遗漏"指令；生成后校验每项在证据中可定位，缺项触发补检索轮。

**阶段二验收**：200 题 ≥ 184（92%）；L 组列表题 ≥ 12/16；跨文档 ≥ 5/8。

## 阶段三：性能与稳定性（可并行启动）

### 3.1 并发 503 修复
- **现状**：4 并发下新代码（多轮生成）31 个 503。
- **方案**：证据受限轮次与主生成共享 90s 总预算；QA 队列与 worker 配置核对（QA_QUEUE_CAPACITY）；LLM 调用失败重试的 sleep 上限与并发请求数解耦；必要时 app 层限流（FastAPI 依赖注入计数）。
- **验证**：200 题 4 并发 0 错误重跑。

### 3.2 延迟优化（30.8s → ≤15s）
- **方案**：检索与生成阶段重叠（检索完成即流式预热）；重排候选上限（RERANK_TOP_K 20→12）与 prompt token 预算精算；定义条款通道命中时跳过宽泛语义检索；多轮生成仅在必要时触发（当前 3 轮 LLM 是延迟主因）。
- **验证**：200 题串行延迟采样。

## 阶段四：长期能力（HyDE + 监管知识图谱）

### 4.1 HyDE 假设文档嵌入
- 定义/条款型问题：LLM 生成"监管术语假设段落"（基于问题语义的伪文档），以其 embedding 补充检索——缓解"问法 ≠ 文档措辞"。
- 成本：每问题 +1 次轻量 LLM 调用（可仅对低置信度问题启用）。

### 4.2 监管文档结构图多跳检索
- 构建"附件-正文-条款-表格"关系图（文件名/附件号/条款号/表格标题为节点与边）；
- 跨文档问题（X 组）第一跳定位主题文档，第二跳按关系边取对应条款/附件；
- 远期可升级为 GraphRAG 式社区摘要用于跨文档综合。

## 风险与控制

| 风险 | 控制 |
|---|---|
| 检索增强误伤合法题（如"内部评级法"映射过强） | 每项增强先跑官方 300 回归 + 对抗样本；限定词表可配置 |
| 条款索引与语料漂移（新文档入库） | 索引随 ingestion 钩子增量更新；失效时自动降级为现有检索 |
| 多轮生成延迟恶化 | 阶段三的预算共享与轮次收敛同步实施 |
| 评测口径（金标结论句过严） | 不修改冻结金标；新批次出题结论按单原子事实拆分（已记录） |

## 执行顺序建议

1. **阶段一（1.1→1.2→1.3）**：检索层结构增强，每子项独立提交 + 回归
2. **阶段三（3.1）**：并发稳定性先行，避免后续评测再遇 503
3. **阶段二**：CRAG 路由（依赖阶段一的基础证据质量）
4. **阶段三（3.2）**：延迟优化（与阶段二的多轮收敛合并做）
5. **阶段四**：按评测收益决定是否启动
