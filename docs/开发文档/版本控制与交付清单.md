# 版本控制与比赛交付清单

本清单依据 2026-07-15 工作区实际状态生成，只做分类，不执行删除、暂存或提交。

## 应纳入版本控制

- 后端源码：`backend/main.py`、`backend/app/api/`、`core/`、`models/`、`schemas/`、`services/`。
- 后端测试：`backend/app/tests/`，包括问答任务、文档生命周期、资源限制、检索、grounding、表格和评测器测试。
- 前端源码与质量配置：`frontend/src/`、`package.json`、`package-lock.json`、`vite.config.ts`、`eslint.config.js`。
- 运行与构建：`Dockerfile`、`docker-compose.yml`、`docker-compose.gpu.yml`、交付版 `.env`、`requirements.in`、`requirements-dev.in`、现有锁定 requirements、`pytest.ini`。
- 启停与交付脚本：`docker-run.bat`、`docker-run.sh`、`run.bat`、`run.sh`、`stop.bat`、`stop.sh`、`rebuild-run.bat`、`dev-run.bat` 兼容别名、`docker-compose.yml`、`docker-compose.gpu.yml`、`scripts/*.ps1` 和本项目实际使用的 `scripts/*.py`。源码提交包必须包含后端/前端测试；本地检查直接运行 pytest、ESLint、Vitest 和前端 build，不再保留额外根目录检查脚本。
- 项目与开发文档：`README.md`、`AGENTS.md`、`docs/开发文档/`、评委说明和学习指南。
- 唯一正式评测结论：`docs/evaluation/final_contest_report.md` 与 `docs/evaluation/final_contest_report.json`。面向官方阅读的 PDF 报告包括 `docs/evaluation/ReguMate_文档解析结果.pdf`、`docs/evaluation/ReguMate_测评报告.pdf` 和 `docs/evaluation/ReguMate_交付说明.pdf`。
- 自制补充数据与脚本：`data/contest-data-self-made/`、`scripts/generate_self_made_artifacts.py`、`scripts/run_self_made_evaluation.ps1`。提交包需包含 `data/evaluation/self_made/` 中的 Markdown/JSON 源报告。

## 必须忽略

- 密钥与本机配置：常规开发仍不提交 `.env.local`；当前小体积提交版例外，`.env` 必须保留项目所有者配置的 DeepSeek API Key，不再保留重复的 `.env.example`。除交付配置文件外不得在代码、README、日志和报告中扩散 key。
- 源码仓库侧的比赛临时数据和暂存副本：`data/contest dataset/`、`data/contest_staging/`。本次小体积提交包按要求包含 `data/contest_dataset/`，用于一键上传知识库和 QA 测试。
- 运行数据：`data/app.db`、`*.db`、`*.sqlite3`、`data/qdrant/`、`data/documents/originals/*`、`data/audit_archives/`。
- 模型与缓存：`data/models/`、`data/model_cache/`、`models/`、`hf_cache/`、`.cache/`。
- 评测明细和中间产物：`data/evaluation/`、`.run-state/`、`reports/generated/`、`outputs/`。例外：提交包需要保留 `data/evaluation/self_made/` 的自制数据报告源文件，以及正式冻结报告所需的白名单 JSON/Markdown。
- 开发环境与构建产物：`.venv/`、`node_modules/`、`frontend/dist/`、`dist/`、`build/`、`__pycache__/`、`.pytest_cache/`。
- 仓库侧交付生成目录和离线大文件：`dist-delivery/`、Docker image tar、模型 tar 和哈希清单的生成副本。解压后的 `ReguMate-Agent` 小体积提交包本身不包含 `dist-delivery/` 文件夹。
- IDE/Agent 本地状态：`.idea/`、`.agents/`、`AGENTS.md`、`*.iml`。`AGENTS.md` 只在本地完整版保留，不进入提交版。
- 真实银行数据、临时上传文件和根目录外部比赛说明二进制文件。

## 提交前人工确认

1. 使用 `git status --short` 确认上述“应纳入”文件没有遗漏；当前工作区存在大量尚未追踪的核心 service、测试、脚本和文档，未纳入前不可制作最终源码包。
2. 使用 `git check-ignore -v <path>` 抽查比赛数据、模型、数据库和上传文件确实被忽略。
3. 运行密钥扫描，确认除交付版 `.env` 外，日志和正式报告不包含 API key、Authorization header 或真实银行信息。
4. 不自动执行 `git add`、`git commit` 或删除用户文件；由项目所有者确认清单后再提交。
5. 从干净副本按 README 构建镜像，核对 health Build ID、镜像 label、源码哈希和正式报告中的 Build ID 一致。
6. 未来修改系统代码、README、配置、脚本或前端构建产物后，必须同步更新提交版生成目录或重新生成提交包。
