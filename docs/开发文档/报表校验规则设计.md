# 报表校验规则开发教程

这个模块带你写出第一批可执行、可测试、可解释的报表校验规则。规则引擎的任务是做确定性判断，Agent 只负责调用和解释，不要把规则写进 prompt。

## 1. 最终要实现什么效果

输入一份解析后的报表数据，输出结构化校验结果：

```json
{
  "rule_id": "RPT_BALANCE_001",
  "passed": false,
  "severity": "high",
  "message": "资产合计与分项加总不一致",
  "expected": 8000.0,
  "actual": 7999.0
}
```

## 2. 文件应该放在哪里

```text
backend/app/rules/
  balance_rules.py
backend/app/schemas/
  validation.py
backend/app/tests/
  test_balance_rules.py
```

## 3. 第一步：定义校验结果模型

文件：`backend/app/schemas/validation.py`

```python
from pydantic import BaseModel


class RuleLocation(BaseModel):
    sheet: str | None = None
    row: int | None = None
    column: str | None = None


class RuleResult(BaseModel):
    rule_id: str
    passed: bool
    severity: str
    message: str
    expected: float | str | None = None
    actual: float | str | None = None
    location: RuleLocation | None = None
    evidence_refs: list[str] = []
```

## 4. 第二步：写第一条勾稽规则

规则 ID：`RPT_BALANCE_001`

规则逻辑：

```text
total_asset = cash + loan + bond
```

文件：`backend/app/rules/balance_rules.py`

```python
from backend.app.schemas.validation import RuleResult


def validate_total_asset(row: dict) -> RuleResult:
    expected = float(row["cash"]) + float(row["loan"]) + float(row["bond"])
    actual = float(row["total_asset"])
    passed = abs(expected - actual) < 0.01

    return RuleResult(
        rule_id="RPT_BALANCE_001",
        passed=passed,
        severity="high",
        message="资产合计与分项加总不一致" if not passed else "资产合计校验通过",
        expected=round(expected, 2),
        actual=round(actual, 2),
        evidence_refs=["REG:reporting_rules_sample#2.1"],
    )
```

## 5. 第三步：处理字段缺失和类型错误

新手容易直接 `float(row["cash"])`，字段缺失时会抛异常。更稳妥的做法是先写辅助函数：

```python
def get_required_number(row: dict, field: str) -> float:
    if field not in row:
        raise ValueError(f"MISSING_FIELD:{field}")
    try:
        return float(row[field])
    except (TypeError, ValueError):
        raise ValueError(f"INVALID_NUMBER:{field}") from None
```

后续可以把错误转换成 `RuleResult`，不要让异常直接暴露给前端。

## 6. 第四步：写规则集合入口

```python
def validate_balance_report(rows: list[dict]) -> list[RuleResult]:
    results: list[RuleResult] = []
    for row in rows:
        results.append(validate_total_asset(row))
    return results
```

第一阶段可以只处理一行样例数据，等 CSV 解析稳定后再支持多行、多 sheet。

## 7. 第五步：写测试

文件：`backend/app/tests/test_balance_rules.py`

```python
from backend.app.rules.balance_rules import validate_total_asset


def test_total_asset_passed():
    row = {"cash": 1000, "loan": 5000, "bond": 2000, "total_asset": 8000}
    result = validate_total_asset(row)
    assert result.passed is True


def test_total_asset_failed():
    row = {"cash": 1000, "loan": 5000, "bond": 2000, "total_asset": 7999}
    result = validate_total_asset(row)
    assert result.passed is False
    assert result.rule_id == "RPT_BALANCE_001"
    assert result.expected == 8000
    assert result.actual == 7999
```

运行：

```powershell
pytest backend\app\tests\test_balance_rules.py
```

## 8. 第六步：让规则结果服务于前端和 Agent

规则结果必须包含：

- `rule_id`：前端展示和测试断言用。
- `passed`：是否通过。
- `severity`：异常严重程度。
- `message`：给人看的提示。
- `expected` / `actual`：证据链需要。
- `evidence_refs`：制度依据或规则依据。

不要只返回 `True` / `False`，否则后续无法解释异常。

## 9. 常见错误

- 没有规则 ID。
- 没有失败样例测试。
- 规则里直接写自然语言解释，但没有结构化字段。
- 金额比较没有考虑小数误差。
- 规则结果没有制度依据引用。

## 10. 完成标准

- 至少实现 `RPT_BALANCE_001`。
- 有通过测试和失败测试。
- 输出结构能被 API、Agent、前端复用。
- 异常结果能进入证据链。
