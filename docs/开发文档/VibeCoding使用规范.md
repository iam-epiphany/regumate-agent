# Vibe Coding 实战规范

这篇文档教你如何把 AI 当成受控的工程协作者。核心原则：你先定义目标、边界、验收标准；AI 负责读少量必要上下文、给出改法，并在你明确要求后执行。

## 1. 当前项目任务示例

一个清楚的任务应该像这样：

```text
请先阅读 AGENTS.md 和 docs/开发文档/API接口设计.md。
目标：完善 POST /api/documents/upload 的错误处理。
允许修改：backend/app/api/documents.py、backend/app/services/document_parser.py、backend/app/tests。
禁止修改：前端、Agent、报表校验、数据库模型。
验收：pytest 通过；上传空 txt 返回 400；上传不支持类型返回 400。
请先说明怎么改，我确认后再执行。
```

## 2. 使用 AI 前准备 6 个信息

| 信息 | 示例 |
| --- | --- |
| 目标 | 新增文档详情接口 |
| 必读文档 | `AGENTS.md`、`API接口设计.md` |
| 允许修改 | `backend/app/api/documents.py` |
| 禁止修改 | 不改前端、不引入向量数据库 |
| 输入输出 | 输入 document_id，返回 chunk 摘要 |
| 验收标准 | pytest 通过，Swagger 可测 |

## 3. 默认流程

1. 让 AI 读最少上下文。
2. 让 AI 说明修改方案。
3. 你确认后，再说“直接修改”。
4. AI 小步修改。
5. AI 运行测试或说明无法运行。
6. AI 总结改了什么、为什么改、怎么验证。
7. 你人工 review。

## 4. 新增功能模板

```text
请先阅读 AGENTS.md 和 docs/开发文档/<相关文档>.md。

我要新增功能：

目标：
输入：
输出：
允许修改：
禁止修改：
验收标准：
测试要求：

请先告诉我开发步骤和文件修改建议，不要直接改代码。
```

确认后：

```text
直接按刚才方案修改代码。
```

## 5. 防止 AI 编造

可以明确写：

```text
不得编造不存在的接口、字段、路径、依赖。
如果文档或代码中找不到，请说明缺失，不要猜。
监管制度回答必须来自 citations。
知识库没有依据时必须拒答。
不要恢复 /api/reports、/api/findings、/api/reviews 旧主线。
```

## 6. 代码审查清单

- 文件路径是否正确。
- 改动是否超出范围。
- 是否有测试。
- 是否能运行。
- 是否有错误处理。
- 是否更新相关文档。
- 是否需要更新 `AGENTS.md`。
- 是否泄露真实数据。
- 是否重新引入报表校验旧代码。

### 做代码审查

```text

```

## 8. 完成标准

- 每次 AI 任务有目标、边界和验收。
- AI 默认先讲方案，不直接改代码。
- 明确要求后才执行修改。
- 修改后必须说明改了什么、为什么改、怎么验证。
- 人工 review 后再进入提交。
