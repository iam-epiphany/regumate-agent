# 项目目录结构

本文档说明当前 RAG-only 版本的目录边界。当前阶段只做“监管制度与统计报表口径文档的可信 RAG 问答”，不再保留报表校验、finding、review、规则引擎页面和接口。

## 2. 每层职责

| 目录 | 当前职责 |
| --- | --- |
| `backend/app/api/` | FastAPI 路由，负责 HTTP 入参、出参和错误码 |
| `backend/app/schemas/` | Pydantic 请求和响应模型，也就是 API 契约 |
| `backend/app/models/` | SQLAlchemy 数据表模型 |
| `backend/app/services/` | 文档保存、解析、切块、检索、问答、审计等业务逻辑 |
| `backend/app/core/` | 数据库连接、建表等基础设施 |
| `frontend/src/api/` | 前端调用后端接口的函数 |
| `frontend/src/pages/` | 工作台、知识库、可信问答、审计日志页面 |
| `data/documents/originals/` | 运行时上传原文件，必须忽略提交 |
| `data/regulations/` | 可提交的脱敏演示制度文档 |

## 3. 当前不再使用的目录

以下目录或模块不属于当前阶段：

- `backend/app/rules/`
- `backend/app/tools/`
- `backend/app/agents/`
- 报表校验样例 `data/samples/`
- 报表规范配置 `data/specs/`
- 异常案例 `data/cases/`

这些能力可以在未来重新引入，但必须先写清楚新的 API 契约、数据模型和测试计划。

## 4. 新增文件放哪里

| 要新增的内容 | 放置位置 |
| --- | --- |
| 新接口 | `backend/app/api/` |
| 新请求/响应字段 | `backend/app/schemas/` |
| 新数据库表 | `backend/app/models/` |
| 文档解析逻辑 | `backend/app/services/document_parser.py` |
| 检索或回答逻辑 | `backend/app/services/rag_service.py` |
| 审计记录逻辑 | `backend/app/services/audit_service.py` |
| 前端接口调用 | `frontend/src/api/` |
| 前端页面 | `frontend/src/pages/` |
| 后端测试 | `backend/app/tests/` |

## 5. 验收标准

- `backend/main.py` 只负责应用装配、建表、挂载路由和静态前端。
- 代码中不再引用 `/api/reports`、`/api/findings`、`/api/reviews`。
- 前端导航只包含工作台、知识库、可信问答、审计日志。
- 运行时文件进入 `data/app.db` 和 `data/documents/originals/`，不提交到 Git。
