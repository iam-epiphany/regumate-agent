# 项目目录结构开发教程

这篇文档带你把当前早期项目整理成适合继续开发的工程结构。目标不是一次性做复杂架构，而是让后端、前端、数据、测试、文档各有位置，新手知道文件该放哪里，AI 也不会乱塞代码。

## 1. 最终要实现什么效果

完成后，项目应该具备下面的结构：

```text
backend/
  main.py
  app/
    api/
    schemas/
    services/
    rules/
    rag/
    tools/
    agents/
    tests/
frontend/
  src/
data/
  samples/
  regulations/
  cases/
  uploads/
  index/
docs/
  开发文档/
```

你应该能回答三个问题：

- 新增一个接口放在哪里？
- 新增一条报表校验规则放在哪里？
- 新增一份样例 CSV 或异常案例 JSON 放在哪里？

## 2. 当前项目起点

当前后端入口是：

```text
backend/main.py
```

它现在只负责创建 FastAPI 应用和健康检查。随着功能增加，不要继续把上传、校验、RAG、Agent 逻辑都写在 `main.py` 里。

## 3. 第一步：创建后端分层目录

在 PowerShell 中执行：

```powershell
New-Item -ItemType Directory backend\app\api -Force
New-Item -ItemType Directory backend\app\schemas -Force
New-Item -ItemType Directory backend\app\services -Force
New-Item -ItemType Directory backend\app\rules -Force
New-Item -ItemType Directory backend\app\rag -Force
New-Item -ItemType Directory backend\app\tools -Force
New-Item -ItemType Directory backend\app\agents -Force
New-Item -ItemType Directory backend\app\tests -Force
```

每个目录的职责：

| 目录 | 放什么 |
| --- | --- |
| `api/` | FastAPI 路由，例如上传接口、校验接口 |
| `schemas/` | Pydantic 请求和响应模型 |
| `services/` | 业务逻辑，例如保存文件、读取报表 |
| `rules/` | 报表校验规则 |
| `rag/` | 制度文档入库、检索、引用 |
| `tools/` | Agent 可调用工具 |
| `agents/` | Agent 工作流编排 |
| `tests/` | 后端测试 |

## 4. 第二步：让 `main.py` 只做应用装配

`backend/main.py` 后续应该保持很薄，主要做三件事：

1. 创建 `FastAPI` 实例。
2. 注册 router。
3. 提供基础健康检查。

示例结构：

```python
from fastapi import FastAPI

app = FastAPI(title="FilingLint Agent API")


@app.get("/health")
def health_check():
    return {"status": "ok"}
```

等你新增 `reports.py` router 后，再在 `main.py` 中挂载：

```python
from backend.app.api import reports

app.include_router(reports.router, prefix="/reports", tags=["reports"])
```

## 5. 第三步：创建数据目录

样例数据和运行时数据分开：

```powershell
New-Item -ItemType Directory data\samples -Force
New-Item -ItemType Directory data\regulations -Force
New-Item -ItemType Directory data\cases -Force
New-Item -ItemType Directory data\uploads -Force
New-Item -ItemType Directory data\index -Force
```

目录职责：

| 目录 | 用途 | 是否建议提交 |
| --- | --- | --- |
| `samples/` | 脱敏样例报表 | 是 |
| `regulations/` | 样例制度文档 | 是 |
| `cases/` | 脱敏异常案例 | 是 |
| `uploads/` | 本地上传文件 | 否 |
| `index/` | RAG 索引产物 | 否 |

后续建议把 `data/uploads/` 和 `data/index/` 加入 `.gitignore`。

## 6. 第四步：新增文件时怎么判断位置

按这个规则判断：

| 你要写的东西 | 放置位置 |
| --- | --- |
| 一个 HTTP 接口 | `backend/app/api/` |
| 请求/响应字段 | `backend/app/schemas/` |
| 保存上传文件 | `backend/app/services/` |
| 校验资产合计 | `backend/app/rules/` |
| 制度检索 | `backend/app/rag/` |
| 给 Agent 调用的工具 | `backend/app/tools/` |
| 串联工具的流程 | `backend/app/agents/` |
| pytest 测试 | `backend/app/tests/` |
| CSV 样例 | `data/samples/` |
| 历史异常案例 | `data/cases/` |

## 7. 常见错误

- 把所有逻辑写进 `backend/main.py`。
- 在 `api/` 里直接写大量业务处理。
- 在测试里使用真实银行数据。
- 把运行时上传文件提交到仓库。
- 前端手写后端不存在的字段。

## 8. 如何验收

执行：

```powershell
Get-ChildItem -Recurse -Directory backend\app
Get-ChildItem -Directory data
```

通过标准：

- 后端目录分层存在。
- `backend/main.py` 没有堆业务逻辑。
- 样例数据目录和运行时目录分开。
- 新手能根据表格判断文件放置位置。
