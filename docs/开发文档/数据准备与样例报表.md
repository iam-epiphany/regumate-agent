# 数据准备与知识库样例

当前阶段不再准备报表校验 CSV 样例，也不维护 `STAT_BALANCE_DEMO` 报表规范。数据准备的目标改为：提供可信 RAG 问答所需的脱敏监管制度、填报说明、指标口径文档样例。

## 1. 数据类型

| 数据类型 | 用途 | 当前状态 |
| --- | --- | --- |
| 监管制度文档 | 回答制度依据类问题 | 支持上传 |
| 填报说明 | 回答统计口径、字段解释类问题 | 支持上传 |
| 指标口径文档 | 回答指标范围、口径边界类问题 | 支持上传 |
| 报表样例 CSV | 报表校验测试 | 当前阶段不做 |
| 异常案例 JSON | Agent 排查与闭环 | 未来扩展 |

## 2. 支持格式

第一版支持以下文档格式：

- `.txt`
- `.md`
- `.docx`
- 可提取文本的 `.pdf`

扫描版 PDF 暂不做 OCR。如果 PDF 无法提取文本，后端应返回清楚的 400 错误。

## 3. 运行时数据位置

```text
data/
  app.db
  documents/
    originals/
  regulations/
```

说明：

- `data/app.db` 是 SQLite 数据库，保存文档、chunks、问答日志和审计日志。
- `data/documents/originals/` 保存用户上传的原始文件。
- 以上运行时数据不提交 Git。
- `data/regulations/` 可以保存脱敏演示文档，用于教学和演示。

## 4. 建议准备的演示文档

可以准备几份短小的 Markdown 或 TXT 文件，例如：

```md
# 监管统计填报说明样例

## 普惠小微贷款统计口径

普惠小微贷款统计应以填报说明规定的客户范围、贷款用途、金额口径为准。系统回答该问题时必须引用本段或其他已入库依据。

## 数据质量要求

报送数据应做到来源清楚、口径一致、可追溯。无法从知识库确认的问题，应提示无法给出确定回答。
```

注意：样例必须脱敏，不要提交真实银行内部制度、客户数据、账号、证件号、手机号或敏感机构信息。

## 5. 上传后的数据流

```mermaid
flowchart LR
  File["上传 txt/md/docx/pdf"] --> Save["保存原文件"]
  Save --> Parse["解析文本"]
  Parse --> Chunk["切分 chunk"]
  Chunk --> DB["写入 SQLite"]
  DB --> QA["问答检索引用"]
```

## 6. 验收标准

- 上传非空 `.txt` 或 `.md` 后能生成 document 和 chunk。
- 空文档或无法解析文档返回 400。
- 文档列表能显示文件名、类型、大小、chunk 数和状态。
- 问答命中知识库时返回引用。
- 问答无命中时拒答，不编造。
