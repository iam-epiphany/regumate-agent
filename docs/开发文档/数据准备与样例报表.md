# 数据准备与样例报表开发教程

这个模块负责给开发、测试、演示提供可信的脱敏数据。没有好样例，规则、RAG、Agent、前端页面都很难稳定开发。

## 1. 最终要实现什么效果

你需要准备三类数据：

- 样例报表：正常报表和异常报表。
- 样例制度：用于 RAG 检索和引用。
- 历史案例：用于根因分析和闭环沉淀演示。

目标目录：

```text
data/
  samples/
    balance_valid.csv
    balance_invalid_total.csv
  regulations/
    reporting_rules_sample.md
  cases/
    case_balance_total_001.json
```

## 2. 第一步：确定一个最小报表类型

MVP 不要一开始覆盖所有监管报表。先做一个“资产负债简表”样例。

建议字段：

| 字段名 | 类型 | 示例 | 说明 |
| --- | --- | --- | --- |
| report_date | string | 2026-06-30 | 报表日期 |
| org_code | string | DEMO_BANK_001 | 机构代码 |
| cash | number | 1000.00 | 现金类资产 |
| loan | number | 5000.00 | 贷款类资产 |
| bond | number | 2000.00 | 债券类资产 |
| total_asset | number | 8000.00 | 资产合计 |

第一条勾稽关系：

```text
total_asset = cash + loan + bond
```

## 3. 第二步：创建正常样例 CSV

文件：`data/samples/balance_valid.csv`

内容示例：

```csv
report_date,org_code,cash,loan,bond,total_asset
2026-06-30,DEMO_BANK_001,1000.00,5000.00,2000.00,8000.00
```

这个文件用于验证“规则通过”的场景。

## 4. 第三步：创建异常样例 CSV

文件：`data/samples/balance_invalid_total.csv`

内容示例：

```csv
report_date,org_code,cash,loan,bond,total_asset
2026-06-30,DEMO_BANK_001,1000.00,5000.00,2000.00,7999.00
```

这个文件用于验证“资产合计不等于分项加总”的场景。

## 5. 第四步：创建样例制度文档

文件：`data/regulations/reporting_rules_sample.md`

内容示例：

```md
# 监管报送样例制度

## 2.1 资产合计填报口径

资产合计应等于现金类资产、贷款类资产、债券类资产等资产分项金额的合计。

## 2.2 数据质量要求

报送数据应保证字段完整、金额类型正确、合计项与分项保持一致。
```

注意：这是演示用虚构制度，不要放真实监管文件全文。

## 6. 第五步：创建历史异常案例

文件：`data/cases/case_balance_total_001.json`

内容示例：

```json
{
  "case_id": "CASE_BALANCE_TOTAL_001",
  "report_type": "balance",
  "finding": "资产合计与分项加总不一致",
  "root_cause": "填报模板中的资产合计公式漏计债券类资产",
  "evidence_refs": [
    "RULE:RPT_BALANCE_001",
    "REG:reporting_rules_sample#2.1"
  ],
  "review_result": "confirmed",
  "created_at": "2026-07-05T12:00:00+08:00"
}
```

## 7. 第六步：设计异常覆盖矩阵

至少准备这些样例：

| 样例文件 | 覆盖问题 | 预期结果 |
| --- | --- | --- |
| `balance_valid.csv` | 正常数据 | 全部通过 |
| `balance_invalid_total.csv` | 勾稽关系错误 | 命中 `RPT_BALANCE_001` |
| `balance_missing_field.csv` | 缺少字段 | 命中字段完整性规则 |
| `balance_invalid_type.csv` | 金额不是数字 | 命中类型规则 |
| `balance_empty_value.csv` | 必填字段为空 | 命中非空规则 |

## 8. 如何在代码里使用样例

测试中不要硬编码一大段 CSV，优先读取文件：

```python
from pathlib import Path

SAMPLES_DIR = Path("data/samples")

def test_balance_valid_file_exists():
    assert (SAMPLES_DIR / "balance_valid.csv").exists()
```

## 9. 常见错误

- 使用真实银行客户数据。
- 样例只有异常，没有正常通过样例。
- 文件名看不出测试目的。
- CSV 字段名和规则代码字段名不一致。
- 历史案例没有 evidence refs，后续无法生成证据链。

## 10. 完成标准

- `data/samples/` 至少有一个正常样例和一个异常样例。
- `data/regulations/` 至少有一个可被 RAG 切分的样例制度文档。
- `data/cases/` 至少有一个历史异常案例 JSON。
- 样例数据全部脱敏或虚构。
- 每个异常样例都能对应到一条规则或一个测试。
