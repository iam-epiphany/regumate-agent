# 前后端协作说明

ReguMate 当前采用前后端分离开发、生产构建后由 FastAPI 托管静态资源的方式。

## 后端

- FastAPI 应用入口：`backend/main.py`。
- API 前缀：`/api`。
- OpenAPI 文档：`/docs`。
- 数据库：`data/app.db`。
- 上传原文：`data/documents/originals/`。

## 前端

- Vite 应用目录：`frontend/`。
- 构建命令：`npm run build`。
- 构建产物：`frontend/dist/`。
- FastAPI 会在构建产物存在时托管根路径页面和 `/assets`。

## 联调流程

1. 后端启动后访问 `/api/health`。
2. 前端工作台调用健康检查。
3. 上传文档时先展示 XHR 真实字节进度；收到 HTTP 202 后按 `document_id` 轮询持久化处理快照，完成后刷新列表。
4. 选择文档查看 chunk。
5. 问答页提交问题并展示回答与引用。
6. 审计页查看操作日志。

## 约束

- 上传接口接受 `Idempotency-Key`；同一键重复提交返回原任务。解析、切片和索引的真实阶段来自 `GET /api/documents/{id}/processing`，前端不得模拟。
- 问答接口要求 `client_request_id`；浏览器在 POST 前持久化该 ID，POST 响应丢失时用同一 ID 重试。后端任务快照是唯一事实源，短暂断网只显示重连。
- 普通模式 `include_debug=false`，只显示用户可理解的回答、证据强度、引用和错误文案；Prompt、chunk ID、模型分数与原始错误只在技术模式显示。
- 所有 HTTP 错误保留兼容 `detail`，并统一提供 `error={code,message,stage,retryable,request_id}`；响应头提供 `X-Request-ID`。
- MVP 使用持久化任务轮询，不新增 WebSocket；旧 SSE 接口只用于兼容和诊断。
- 前端不要硬编码未实现接口。
- 后端不要返回没有 schema 约束的临时结构。
- 修改 API 时同步更新 `API接口设计.md` 和 `V0接口文档.md`。
