# 官方 300 题开放式问答 v3 基线报告(首跑冻结)

**报告状态:** 2026-08-01 首跑冻结;后续任何运行均为回归,与本文配对比较,不得覆盖本报告数据。

## 1. 背景

官方题库原始形式为选择题,此前 300/300 只能证明"带选项时能从检索证据和候选项中完成选择"。为验证无选项的自主事实定位、组织完整答案与来源约束能力,本项目建立 open-official-v3 开放式变换,并修复 v2 的测量污染(见 `official_open_300_v2_root_cause_report_20260801.md`)。

## 2. v3 变换设计(修复 v2 两个缺陷)

| v2 缺陷 | v3 修复 |
|---|---|
| 200 道事实题去掉选项后压成 30 个重复题面组(差异只在选项里),任何"去选项+保留题面"都使同制度多题变成同一问题 | 事实题改为**验证式问答题**:金标语句(官方正确选项完整表述)锚定进题面,要求系统"判断该表述是否符合材料内容并给出制度依据"(`verify_fact`,每题唯一且必有答案) |
| 33 道表格比较题丢失候选集合,金标只留指标名 | 候选集合(官方 options)嵌入题面,要求"给出数值最高的指标名称和对应数值"(`table_comparison`);金标数值由 `build_open_v3_gold.py` 从语料单元格索引独立计算(赢家指标以官方答案为权威,数值独立读取) |
| — | 表格取数/计算题原题面已是开放问句,原样保留(`direct_table`) |

## 3. 冻结产物与校验

- 题集:`data/evaluation/official_open_300_v3/`
  - `open_questions.jsonl`(300 条,仅题面与元数据,无答案)
  - `open_reference_answers.jsonl`(300 条金标,独立于生产代码)
  - `open_v3_gold.json`(33 道比较题金标数值,33/33 成功,赢家指标与官方答案全部一致)
  - `open_manifest.json`(审计结果 + 全部哈希)
  - `open_results_v3_first.json`(首跑结果,300/300 无运行错误)
  - `open_semantic_score_v3_first.json`(judge 评分)
- 审计(`open_manifest.json`):**passed=true,0 错误**——题面唯一性(重复题面必须同金标)、金标完整性、选项泄漏(仅允许锚定金标/候选集)、无选择题措辞残留、制度锚完整。
- 变换版本:`open-official-v3`;judge 版本:`open-semantic-judge-v2`。

## 4. 金标口径备注(题目质量审计发现)

`build_open_v3_gold.py` 对 33 道比较题独立计算"数值最大候选",与官方答案比对:

- **24/33**:独立最大值 = 官方答案(一致,金标可靠)。
- **9/33 记录口径差异**(`gold.remarks`,官方答案保留为权威):
  - Q044/52/60(人身险月度表):独立最大为"新增保险金额"(约 9.3e6,保额口径),官方答案为"原保险保费收入"。
  - Q045/53/61(保险业经营表):独立最大为"总资产"(约 3.5e5),官方答案为"原保险保费收入"。
  - Q051/59/67(产险月度表):独立最大为"保险金额"(约 1.2e8),官方答案为"原保险保费收入"。
- **结论**:官方出题把"保险金额/新增保险金额/总资产"等异口径指标放进"数值最高"候选,实际按保费类指标口径判定。这证实了此前对"题目和答案质量"的怀疑——v3 将这些差异显式记录为 remark,金标仍以官方答案为权威(与官方选择题判定一致),系统若按纯数值独立计算会与官方判定不一致,属于**题目口径问题而非系统缺陷**。

数值口径:题面未指定期间时,金标给出该指标在题面口径下的**合法取值区间**(`expected_value_range`,来自单元格索引),judge 按区间与数量级判定,避免因期间选择差异误判。

### 5.2 表格类(确定性路径,67 题 direct_table + 33 题 table_comparison)

- 表格取数/计算:100% 走确定性链路,毫秒级。
- **表格比较:33/33 指标名正确**(v2 时仅 7/33),数值与金标区间一致——v2 的失败确为题面变换污染,v3 修复后该能力已验证。

### 5.3 文本类(200 题 verify_fact)

- 90 题 LLM 正常生成;109 题**降级为 extractive_fallback**——首跑时 DeepSeek API 不稳定(偶发超时/失败)是主因,需回归复测确认;1 题拒答。
- 准确率与失败类别分布见 judge 评分与 analyze 分析(文件冻结后补充)。

### 5.5 基线结论

1. **题集质量**:v3 审计通过(题面唯一、金标完整、无选项泄漏);9/33 比较题存在"官方口径 vs 独立数值最大"差异,已记录 remark。
2. **多事实检索**:47.0%(31/66),相对 v2 的 0/66 是实质改善——用户对"题目和答案有问题"的怀疑部分成立,题面修复后能力可测。
3. **系统短板(待优化后回归对比)**:
   - LLM 生成降级率高(基线 109/300)——已定位根因:deepseek-v4-flash 对长 prompt 输出 reasoning_content,900 tokens 预算被思考耗尽导致空输出;已修复(max_tokens 3000 + 4 次交替重试),回归待验证。
   - 文本题校验失败后走摘录降级,答案质量与完整性受限。
