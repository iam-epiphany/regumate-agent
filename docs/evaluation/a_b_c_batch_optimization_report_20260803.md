## 3. workbench 100（去锚 100 题）与 LLM 服务漂移判定

| 运行 | 分数 | 说明 |
|---|---|---|
| 基线（8-03 02:46，20e58a9 容器） | **79/100** | 存档基线 |
| A 批 #1 | 75/100 | 失败 25 题 |
| A 批 #2（同容器重跑） | 73/94 | 3 题缺失（运行中断） |
| B 批 | 72/100 | 运行期间出现"生成服务暂不可用" |
| C 批 #1 / #2 / 单 worker | 72 / 71 / 71 | 三次运行 |
| **基线代码现在**（20e58a9 重建容器，当前服务状态） | **76 / 72** | 两次运行 |

**判定：workbench 分数下降的主因是 LLM 服务行为漂移，非代码回归。** 证据链：

1. **基线代码（20e58a9）在当前服务下无法复现 79**：重建基线 GPU 容器（真实数据+真实 LLM）跑完整 workbench 两次，得 76/72——与 A/B/C 批分数区间（71-75）完全重叠。基线代码自身就在 72-76 波动。
2. **稳定失败题跨代码版本复现**：BW-T06 在 A 批两次、B 批、C 批、手动复测、以及基线代码复测中全部以同一模式失败（"已检索到相关依据，但生成答案未通过事实校验"结构化拒答，`semantic_conflict_count=1`）——基线代码现在跑 T06 同样失败。
3. **失败模式集中在生成/校验环节**：两批之间失败题漂移大（C批1 与 C批2 仅 25/28 交集），全部为 `answer_generation` 类失败（非检索、非拒答边界）。多个失败题手动单发复测即恢复正常回答（如 BW-L04/X04/T07/T09）。
4. 失败题高度集中在长答案开放题（threshold_rule/scope/cross_document），这类题对 LLM 生成质量敏感：生成内容一旦偏离证据，语义校验检出冲突 → 修复失败 → 结构化拒答。

**残留差异说明**：基线代码 now 两次均通过而 C 批失败的题有 5 道（BW-D15/R19/T07/T09/T13），全部为 answer_generation 类，且其中 T07 在 C 批内部两次运行结果不同——处于运行波动范围内，无法在单次运行证据下归因于代码。若需彻底归因，需在 LLM 服务状态稳定后重跑基线+当前代码各 2-3 轮取中位数。

## 4. 风险与取舍

- **A1 回退**：实测 batch=1 与 batch=4 的 BGE-M3 dense 向量最大差 2.5e-7（fp16 舍入），理论上可翻转边界候选排序。A 批两次 workbench 运行确认 BW-T06 稳定回退后，先回退 A1 保守处理；后续 T06 经基线代码实验证实为 LLM 漂移而非 A1。**当前默认保持 batch=1（零风险），`QUERY_EMBEDDING_BATCH_SIZE` 环境变量可调回 4 换取 -14% 延迟**（官方 300 在 A1=4 时同样 300/300）。
- A3（重排批上限 24）实测与 8 完全一致（0 差异），保留。
- B 批的 B1/B3/B5 改变了检索门/claim 过滤语义，是官方 300 保持 300/300 下最"有行为"的改动；workbench 无证据表明其造成可复现回退。

## 5. 结论

1. **官方 300 硬门槛：A/B/C 三批全部 300/300，无回归。**
2. **workbench 100：79 基线在当前 LLM 服务状态下不可复现（基线代码自身 72-76）；当前代码 71-75，与基线代码当前水平重叠，无证据表明代码造成可复现回退。**
3. **性能**：A 批组合优化在官方 300 上 avg -14%/p95 -23%（A1=4 时）；A1 回退后 p95 仍优于基线。
4. **工程质量**：单元测试 535 passed 全绿、死代码净删 354 行、审计 0 发现、评测输出全部原样归档于 `data/evaluation/官方300选择题-回归{A,B,C}批/` 与 `data/evaluation/去锚100题/regression_{a,b,c}_batch*/`。
