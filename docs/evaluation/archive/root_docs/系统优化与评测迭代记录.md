> 用途：内部项目复盘、后续优化和答辩准备。  
> 本文档完整保留历史失败、题目审核、根因分析、代码修改、回归与独立评测过程。  
> 本文档不等同于对外《系统评测报告》，可以不进入最终提交包。

## 1. 文档规则

每轮记录必须区分：

- 官方数据集结果；
- 原始 100 题首跑结果；
- 18 道失败题修复回归结果；
- 审核后的 100 题版本结果；
- 新增 50 道独立题结果；
- 最终发布评测结果。

不得：

- 混合不同批次统计；
- 删除中间失败；
- 把回归成绩包装成独立盲测；
- 把题目问题误判为系统问题；
- 用最终高分覆盖历史失败；
- 在没有原始证据时补写结论。

每项关键结果尽量记录：

- 测试时间；
- Git commit；
- 题集版本；
- questions / gold 哈希；
- 模型和关键配置；
- SQLite 和 Qdrant 快照；
- 运行命令；
- 原始结果路径；
- 主要指标；
- 是否出现回退。

## 4. 当前主要判断

最近一轮总结的结论：

**可以继续，但必须调整方向。**

继续工作的价值在于：

- 可信链、评测体系和 RAG 能力已有实质提升；
- 官方基础能力较强；
- 自研困难集可以展示系统真实上限；
- 仍有机会将项目收敛为可信、可解释、可交付的成熟作品。

当前不应继续：

- 新增花哨功能；
- 围绕固定题号打补丁；
- 追求没有题目审核支撑的漂亮分数；
- 无限增加 helper 和 fallback；
- 把回归结果当独立评测。

当前应优先：

1. 审计工作区；
2. 复核官方数据集；
3. 逐题审核 18 道失败题；
4. 只修复有效失败的通用根因；
5. 审核并重新校准现有挑战集；
6. 从官方困难题逐步生成合理新题；
7. 独立评测达到 90%；
8. 收敛性能和复杂度；
9. 精简对外报告；
10. 保留完整内部记录。

### 本质问题

这 19 道不是单题知识点问题，主要对应 4 个通用机制：

1. 多 aspect 问题没有稳定的“全覆盖合成器”。系统能检索到部分证据，但在生成或 deterministic known-fact 路径中容易只输出部分 aspect，形成局部正确、整体漏项。
2. Query planner 的同义触发仍不够系统化。`损失吸收顺序`、`回复时限`、`控制银行询证函全过程`、`终极利率暂定值` 等表达，原逻辑没有统一归入已有监管 aspect。
3. mixed regulation + table 的整体机制不足。制度事实和结构化表格事实应由一个跨模态合成器统一产出；当前仍容易出现制度答对但表格值漏掉，或表格结果被文本 known-fact 路径覆盖。
4. 选择题跨文件证据矩阵仍是弱点。选项中多事实、多文件同时存在时，当前证据召回和选项级校验容易因少数事实未召回而整体拒答。

其中第 3、4 类属于系统整体机制边界，不适合继续用追加少量规则硬补；需要后续设计专门的跨模态 answer composer 和 option evidence matrix 增强。

### 本次二次通用修补
