# 官方 300 题开放式问答评测根因报告

**报告状态：** 冻结结果审计，未修改生产代码、官方 Excel、题面、参考答案、运行结果或语义评分器。

**评测目录：** `data/evaluation/official_open_300_v2/`

## 1. 动机与边界

官方题库原始形式是选择题。此前的 300/300 只能证明系统在能够看到候选项时，能够从检索证据和选项中完成选择；它不能直接证明系统能够在没有候选项时，自主定位事实、组织完整答案并保持来源约束。因此本轮建立 `open-official-v2` 变换：向生产 API 只发送题面和 `options=[]`，再用独立离线语义评审，对比系统答案与官方 `answer_text` 的事实含义。

本报告的目的不是把开放式分数当作新的官方验收门，也不是把每个“错”都归因于生产代码，而是审计这次测量是否有效，区分题面变换错误、评测边界错误和可归因的系统能力缺陷。官方 Excel 和参考答案仅在离线审计中使用；生产代码没有读取它们。

## 2. 方法与不可变产物

1. `scripts/evaluation/open_official_qa.py` 读取官方 300 题，生成公开题面和隔离的参考答案。
2. 事实选择题被改写为“直接给出题目涉及的完整监管事实”，并清空选项；表格比较题被改写为“指出口径下数值最高的指标并给出数值”；原始题干和选项只通过哈希进入参考文件。
3. `run` 阶段向 `/api/qa/ask` 发送 `{"question": ..., "options": []}`，结果逐题检查点写入 `open_results.json`。
4. `judge` 阶段由独立模型只比较事实语义，输出 `correct/confidence/reason`，不参与生产问答。
5. 冻结文件及校验值：
   - `open_questions.jsonl`：300 条；
   - `open_reference_answers.jsonl`：300 条；
   - `open_results.json`：300 条完整响应，`runtime_error_count=0`；
   - `open_semantic_score.json`：`judge_prompt_version=open-semantic-judge-v1`，题面和结果哈希与 manifest 一致；
   - `open_semantic_score.md`：同一评分摘要。

本轮没有覆盖或重写首次结果。后续任何修复都只能生成新的回归文件，并与本报告中的首轮结果配对比较。

## 4. 题面变换有效性审计

### 4.1 制度文本题：200 题被压缩成 30 个重复题面组

200 道 `regulatory_fact` 题去掉选项后只剩 30 个不同题面组，重复组共覆盖 200 道题；组大小分布为 20 组 × 4 题、4 组 × 5 题、4 组 × 17 题、2 组 × 16 题。组内同一题面对应不同 `answer_text`，例如同一制度下原题分别考查定义、适用范围、职责或具体阈值，改写后却都成为同一个“给出完整监管事实”的泛化问题。

因此这 200 题不是 200 个独立、可唯一判定的开放式问题。系统回答其中一个事实时，可能合理但无法同时满足同组另一条参考答案。200 题中 21 题判对、179 题判错，不能把 179 全部解释为检索或生成失败；首先应记录为变换造成的测量效度损失。

### 4.2 表格比较题：比较集合和输出契约发生改变

33 道原题均有四个候选指标/地区，原始 `answer_text` 只表示候选项中的正确指标。v2 将题面改成“整张表中数值最高的指标并给出数值”，却没有把原候选集合和期望数值写入参考答案。于是题意从“在四项中选最大”变成“全表扫描并输出指标+数值”，而评分仍主要比较指标名。Q038、Q039、Q044、Q045 是系统选择“净利润/总资产”而金标保留“不良贷款余额/原保险保费收入”的典型例子；Q046-Q067 还出现系统因无法唯一比较而拒答，但原金标仅为“全国合计/全国”的情况。

这 26 个错误首先是转换和金标契约不一致。下一版若要测开放式表格比较，必须冻结：完整表头路径、候选集合、比较方向、单位、期间、期望指标和期望数值；不能从只含指标名的旧选择题金标反推全表最大值。

## 6. 可归因的系统不足

在扣除题面转换无效性后，本轮仍提供了清晰的工程信号：

1. **开放式多事实检索缺少完整 aspect 契约。** 多事实题为 0/66。检索、重排和生成没有稳定表达“同一问题需要同时满足哪些独立事实、每个事实来自哪个来源”的结构，常出现只返回一个来源或一个条款。
2. **文本证据选择偏向高相似但非目标片段。** 典型回答列举合规、资本或流程条款，却未回答题目要求的定义、适用范围、阈值或职责。引用存在不等于目标事实命中。
3. **生成失败时的降级契约不完整。** 大量答案以“生成服务暂不可用”或“已检索到相关依据但生成答案未通过事实校验”开头，随后直接返回候选摘录。此策略避免编造，但没有把失败原因、缺失事实和需要澄清的槽位结构化呈现；开放式任务因此被判为不完整答案。
4. **表格比较的结构约束不足。** 表格取数与计算均 100%，但比较仅 7/33，说明单元格定位和确定性计算链路可用，跨指标集合枚举、口径筛选、比较方向和“指标名+数值”输出契约仍不稳定。
5. **独立语义评分的适用范围有限。** 评分器适合在题面唯一、参考答案完整时判断事实语义；它不能修复题面欠定，也不能证明另一合理来源就是系统错误。低置信度为 0 只表示评审器按当前输入给出了高置信度结论，不等于所有金标都具备唯一性。

## 7. 后续系统整理建议

### P0：先修评测契约，再修生产链路

- 不把本轮 31.67% 作为生产回归门；冻结本报告和首轮结果。
- 重新设计开放式转换：事实题保留原题干的实体、关系、条件和所有必要限定，不能用同一句泛化模板替换不同选项语义。
- 重新设计表格比较 gold：保留候选集合或明确全表范围，并固化表头路径、期间、单位、比较方向、指标和数值。
- 在任何新开放式运行前，执行独立可答性、唯一性、重复题面、金标完整性和表格坐标审计。

### P1：通用多事实与证据充分性能力

- 将 planner 输出规范化为原子 aspects，每个 aspect 带目标事实、必要条件和来源约束；禁止后续阶段用单一来源覆盖多个 aspect。
- 在答案生成前做 aspect 覆盖检查：缺少任一必要事实时，返回具体澄清/拒答，而不是把相邻摘录拼成答案。
- 让证据选择同时考虑章节/条款路径、来源身份和否定边界，保留每个 claim 的独立引用。
- 将 `generation_status`、事实校验失败、检索不足和服务异常分成稳定的内部状态与用户可读结果。

### P1：表格比较能力

- 复用已验证的表格选择器和 Decimal 计算链路，新增“候选集合枚举 -> 口径过滤 -> 单位归一 -> 比较 -> 输出指标和值”的通用流程。
- 对缺少唯一表头、期间或单位的请求拒答并指出缺槽位；不得在不确定时默认左列/右列或默认合计口径。

### P2：可观测性与回归

- 在安全诊断中记录 aspect 覆盖率、候选来源数、最终引用覆盖率、拒答原因和生成降级原因。
- 在同一冻结有效开发集上做配对回归，再用独立密封集做最终泛化验收；不要连续更换题集后直接比较总分。
- 保留官方带选项 300/300 作为兼容性回归，开放式结果单独命名、单独评分、单独设门。

## 8. 结论

本轮完成了真实的 300 题无选项请求和独立语义评审，但测量结果被开放式转换缺陷显著污染。可以确认的系统事实是：表格取数、表格计算和直接题面保持稳定；多事实文本问答、目标事实证据选择、降级输出和表格比较仍是主要短板。下一步应先修正评测量具并在固定有效题集上验证通用能力，再决定是否投入新的开放式生产优化。不得用本轮 95/300 替换或否定历史官方带选项 300/300，也不得用修改金标或放宽评分器提高分数。
