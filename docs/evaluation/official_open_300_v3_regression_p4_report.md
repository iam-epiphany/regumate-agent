# 官方 300 题开放式问答 v3 回归报告(优化后,配对比较)

**日期:** 2026-08-01
**基线:** `官方300开放问答_baseline_report.md`(首跑冻结)
**回归产物:** `data/evaluation/官方300开放问答/regression_p4_all.json`(系统回答)、`regression_p4_semantic_score.json`(judge 评分)、`regression_p4_failure_analysis.json`(过程分析)
**官方 300 回归(选择题):** `data/evaluation/官方300选择题-验收基线/official_300_results.json` — **300/300 正确,0 错误,avg 1.35s**(AGENTS.md 硬性门禁通过)

## 1. 本回归包含的生产改动(全部通用能力改进)

| 改动 | 内容 |
|---|---|
| P0-1 批量检索合并 | 多 aspect 的 embedding / Qdrant 混合检索 / BGE rerank 合并为单次批量调用(`rag_service._collect_prepared_candidates_many` + `rerank_candidate_groups`);单 aspect 与测试 hook 走原路径 |
| P0-3 rerank 上限 | `RERANK_INFERENCE_BATCH_LIMIT` 4 → 8(GPU 生效,CPU 保持 4/2) |
| P1-1 生成前门禁 | 上下文证据未覆盖全部 required aspect 时,生成前结构化拒答(`ASPECT_GATE_PRE_GENERATION`,MCQ 豁免) |
| P0-2 失败分诊 | aspect 类校验失败走确定性拒答,不再烧 LLM repair 轮;内容类失败仍 repair |
| LLM 可靠性修复(根因) | **deepseek-v4-flash 对长 prompt 输出 `reasoning_content`(思考),`max_tokens=900` 被思考耗尽导致 `content` 恒为空**(流式空流/非流式空 body);修复:`ANSWER_GENERATION_MAX_TOKENS` 900 → 3000,`MAX_ATTEMPTS` 2 → 4 并交替流式/非流式重试,生成超时 18s → 40s |

## 3. 多事实检索 0 → 47% → 83.3% 的归因

1. **题面修复(v3)**:v2 把 200 道事实题压成 30 个重复题面,多事实题全部不可判;v3 锚定金标语句使每题唯一可答。这证实了"题目和答案有问题"的怀疑——测量修复是最大贡献。
2. **LLM 可靠性修复**:max_tokens 3000 后 LLM 真正开始生成结构化答案(基线 109 题因空输出降级为摘录)。
3. 批量检索/门禁/分诊为增量改进。

## 4. 剩余短板(46 题判错,失败类别见 analyze)

- 291 题无系统失败信号但 judge 判错 → **生成内容与金标事实不一致**(内容质量,需逐题分析);
- 5 题低置信评审(需人工复核);
- 4 题结构化拒答(门禁/分诊,属诚实拒答);
- 表格比较 11 题数值口径(官方题面未指定期间,金标区间判定仍有波动)。
