# ReguMate 参赛版演示脚本

演示只从生产问答入口提交问题，不注入答案、来源定位或特殊路由。六个案例在最终版各连续运行 3 次均通过，记录见 `results.md`。

## 1. 演示前检查

```powershell
python scripts/contest/preflight_contest.py --base-url http://127.0.0.1:8000 --check-llm
```

确认输出包含 `preflight-ok`，并检查：

- `device=cuda`（或明确显示 CPU 兼容模式）；
- `embedding_model`、`reranker_model`、`qdrant`、`sqlite` 均为 PASS；
- `online_llm` 为 PASS，且真实模型调用数大于 0；
- 浏览器打开 <http://127.0.0.1:8000> 后能看到当前知识库文档数。

## 2. 通用操作顺序

1. 在问答框粘贴案例问题，点击提交。
2. 等待任务结束；页面显示“已完成”或“已结束（未形成确定结论）”。
3. 在页头切换到“展示视图”。
4. 先看顶部任务区：原问题、来源要求、Agent 分工、预算和实际耗时。
5. 点击一条结论：右侧证据卡和对应计算卡高亮。
6. 点击一张证据卡：定位到使用它的结论。
7. 分别指出“引用可定位 / 事实支持 / 要求完整性”三项状态；只有三项全真才显示全部通过。
8. 展示“智能体协作轨迹”和“运行预算”，说明这是实际记录而不是事后补写。
9. 点击“日常问答”可回到原布局；两种视图使用同一份答案，不重新请求。

## 3. 六个演示案例

### C01 制度查询：定义句与相邻条款的区分

问题：

> 《恢复计划示例（商业银行版）》中，关键功能的定义是什么？

预期展示点：

- 结论引用“提供给第三方的关键业务或产品等金融服务”的定义句，而不是只引用“恢复阶段应优先保护”的相邻段落。
- 侧边依据显示来源文件、章节和原文。
- 三项核验通过；预算类别为普通任务；模型调用约 3 次（规划、生成、核验）。

### C03 跨文档比较：两个来源并列

问题：

> 《恢复计划示例（商业银行版）》与《处置计划建议示例（商业银行版）》中，关键功能的定义是否一致？

预期展示点：

- 主体区出现两个来源的并列卡片，各自有独立证据。
- 结论给出“一致/相同”的判断，并同时引用两份材料。
- 顶部来源要求显示两个必需来源；预算类别为复杂任务，时间预算 240 秒。
- 点击任一结论，右侧只高亮该结论实际依赖的证据。

### C05 表格取数：从单元格到结论

问题：

> 根据监管统计表《2023年3季度保险业资金运用情况表》的工作表“2023年3季度保险资金运用情况表”，请给出“资金运用余额”在“账面余额”列的数值。

预期展示点：

- 结论数值为 275230.6254 亿元（允许千分位格式）。
- 计算/取数记录显示工作表、单元格 B6、单位“亿元”。
- 表格路径不调用生成模型，模型调用数为 0；这与实际执行一致。
- 引用可定位、事实支持、要求完整性三项通过。

### C07 表格计算：操作数、公式、结果

问题：

> 《2023年3季度保险业资金运用情况表》中，银行存款和债券的账面余额分别是多少？两者相差多少亿元？

预期展示点：

- 计算卡显示操作数 B13=21833.23、B14=110034.323。
- 公式显示 `21833.23 - 110034.323 = -88201.093`。
- 结果为 -88201.093 亿元，来源为同一工作表。
- 点击结论会同时高亮对应的计算记录和证据卡。

### C09 制度与数据联合问答：两侧证据缺一不可

问题：

> 《恢复计划示例（商业银行版）》中，关键功能的定义是什么？同时，根据监管统计表《2023年3季度保险业资金运用情况表》的工作表“2023年3季度保险资金运用情况表”，请给出“资金运用余额”在“账面余额”列的数值。

预期展示点：

- 顶部来源要求同时出现制度文件和统计表。
- 主体结论同时包含定义和 275230.6254 亿元。
- 侧边依据同时出现 docx 定义句和 xlsx 单元格 B6。
- 预算类别为复杂任务（两个必需来源），时间预算 240 秒；模型调用约 2 次（确定性规划不调用规划模型，随后生成、核验）。

### C11 证据不足：明确缺口，不编造数值

问题：

> 请给出2026年第四季度保险业资金运用情况表里“资金运用余额”的账面余额。

预期展示点：

- 任务结束状态为“已结束（未形成确定结论）”或“需要补充问题信息”。
- 页面不出现 2025 年或其他期间的数值替代结果。
- 侧边依据显示缺少指定期间；三项核验不会显示全部通过。
- 预算类别为普通任务；失败原因属于证据/期间缺口，不是服务超时。

## 6. 演示时不要做的事

- 不手工修改答案、引用或核验状态。
- 不把普通视图和展示视图说成两次请求；它们是同一结果。
- 不把表格路径的 0 次模型调用解释为“没有工作”；表格定位和确定性计算由业务服务完成。
- 不把 6 个演示案例的通过率说成全量正确率。
- 不在演示中临时切换模型、索引或候选策略；演示前只做预热和就绪检查。
