# 讲解卡：结构坐标与证据面审计

用途：在现有 5/10 分钟演示中增加 60–90 秒，不替换原有主线。  
状态：代码已实现，单测与前端构建通过；官方 300 题开放跑测已完成，结果见 `docs/evaluation/official300_open_20261020.md`。本卡不把该成绩与本轮新增展示能力混为一谈。

## 一句话

ReguMate 不只告诉你“引用了哪份文件”，还把引用解码成“制度 → 章 → 条”的结构坐标；同时把“找到了相关段落”和“问题要求的信息面是否齐全”分开显示。

## 30 秒讲法

> 监管问答里，“相关”不等于“够用”。我们做了两件事：
>
> 第一，把每条引用还原成可复核的结构坐标，比如《消费金融公司管理办法》第二章第十条，而不是只显示一个文件名。
>
> 第二，在证据整编后做一次确定性的信息面审计：来源、目标词、数值阈值、适用条件、定义句式、表格操作数，逐项标出有没有出现。它不调用模型，也不替代最终核验，但能解释“为什么这条回答还缺依据”。

## 现场操作

1. 提一个能命中制度条文的问题，打开引用卡片，指出结构坐标。
2. 切到展示视图，指出“证据面审计”中的：
   - 覆盖状态（信息面完整 / 部分覆盖 / 关键信息面缺失）；
   - 候选 / 入选数量；
   - 结构补全条数；
   - 待补信息面。
3. 说明审计结果与“引用可定位 / 事实支持 / 要求完整性”是并列展示，不互相替代。

## 可以说的三句话

- “引用可以解码成制度、章、条，评委能按坐标回到原文。”
- “我们把相关性和充分性分开显示，缺哪一类信息面会明确列出来。”
- “这套审计是确定性的，不增加模型调用。”

## 不能说的话

- 不能说已经构建了完整的法规知识图谱；
- 不能说所有引用都精确到款、项、目；
- 不能说审计通过就等于法律判断正确；
- 不能说已经实现在线 BFR、FCA-MS 或论文复现；
- 不能把开放问答题的跑测结果说成原始选择题成绩提升；
- 不能把 300 题开放跑测的 76% 说成 95% 的选择题成绩。

## 与两篇论文的对应关系

| 论文思想 | 本项目落地 | 没有做什么 |
|---|---|---|
| 结构驱动分块/导航 | 复用现有 `section_path` + 条号索引，生成统一结构坐标 | 没有另建图数据库 |
| 引用可解码 | `Citation.structure_locator`，可直接序列化、比较 | 没有声称条号命中率 |
| 一跳扩展 | 保留现有邻块/跨文档引用扩展，并记录扩展成本 | 没有无条件扩大父块 |
| 相关性 ≠ 充分性 | 要求级信息面审计 + 缺口列表 | 没有用参考答案做在线判断 |
| 预算化补检 | 记录扩展条数与成本，为 P1 留接口 | 本轮未启用新的补检循环 |

详细分析见 `docs/tech-radar/2026-10-structure-kg-bfr.md`，落地与验证见 `docs/tech-radar/2026-10-implementation-notes.md`。
