# ReguMate 项目完整开发计划

## 项目目标

系统面向银行统计报送、合规和财务人员，以官方监管制度、填报说明和统计报表构建可信知识库；回答必须提供可追溯证据，无依据时拒答。监管规则和最终法律效力判断不交给 LLM 自动生成。

## 当前完成状态

1. P1 文档身份可信链已实现：保守抽取、字段来源轨迹、允许未知、部分更新、人工确认快照、修改后撤销确认、操作日志和前端紧凑身份卡。
2. 500 份官方文档已执行幂等身份回填；不覆盖人工、manifest 或 URL 导入数据，不重算 embedding。回填后的 SQLite/Qdrant 46,585 个 chunk/point 完全一致。
3. 已退役的实验题集、专用脚本和派生报告已从源码、报告生成、文档及打包规则中清除；官方公式解析与回归工作予以保留。
4. 官方 500 文档 100 题挑战集已完成构建、三步证据核验、结构校验和哈希冻结。40 题开发集用于通用修复，不存在题号或答案特判。
5. 首次 60 题封存运行已保存原始响应并完成离线独立评分，结果未达到门槛；失败证据永久保留，不运行和发布全量 100 题成功结论。

## 后续优先级

1. 以失败分类为输入，优先改善跨文件与制度—报表联合问题的 query aspect 拆解、分来源召回和结论级证据覆盖。
2. 优化外部 LLM 阶段与高风险语义核验延迟，使 GPU P95 回到 8 秒以内且相对冻结基线回归不超过 30%。
3. 所有改进必须是通用能力，禁止按题号、固定答案、固定文档 ID 或金标内容特判。
4. 代码与评测器再次冻结后，只能把后续封存运行称为“回归复测”；若未来获得银行监管专家复核，应新增独立复核记录，不回写伪造现有 `codex_verified` 状态。

## 交付顺序

先完成源码、测试、文档和评测证据，再同步唯一 `dist-delivery/ReguMate-Agent`。提交版执行秘密扫描、文件清单和 SHA-256 校验，不包含本地 `AGENTS.md`、运行数据库、上传文件、缓存、模型或第二份 staging。当前任务不创建 Git 提交或推送。
