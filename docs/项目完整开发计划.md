# ReguMate 项目完整开发计划

## 1. 项目目标

ReguMate 是一个学习型可信 RAG 问答系统，面向银行业监管制度、统计报表填报说明、指标口径文档和 Excel 统计报表证据。

当前阶段目标是完成可运行的可信 RAG 竞赛 MVP，并让学习者能够按“解析—索引—检索—生成—校验—引用”顺序理解代码。
检索层使用 BGE-M3、Qdrant hybrid search 和 BGE reranker；回答层使用确定性表格计算与配置化 DeepSeek，并坚持“先证据、后答案、生成后校验、无依据拒答”。

## 2. 当前阶段范围

当前只实现：

- 文档上传。
- 文档文本解析，以及 `.doc/.xls/.xlsx` 多格式解析。
- Excel 工作表、表标题、单位、期间、行列标签、单元格坐标和值的结构化入库。
- token-aware chunk 切分与 SQLite 入库。
- Qdrant 向量索引。
- BGE-M3 embedding 检索。
- BGE reranker 重排。
- QueryPlanner 的 `text/table/mixed` 检索计划。
- Excel 取数、比较和差值/合计/占比等基础计算上下文。
- 带引用回答。
- 无依据拒答。
- 审计日志。
- React 工作台。
- DeepSeek 结构化最终答案、claim-citation 绑定与事实校验。
- 240/60 固定评测、30 道派生拒答题和批量断点入库。

当前不实现：

- 规则引擎。
- 人工复核。
- 审查报告。
- 复杂任务编排。

## 3. 架构原则

- 后端保持 `api / schemas / models / services / core` 分层。
- `backend/main.py` 只负责创建应用、挂载中间件、注册路由和托管前端构建产物。
- API 层只处理 HTTP 契约和异常转换。
- service 层承载上传、解析、chunk、embedding、向量索引、检索、rerank、问答和审计逻辑。
- 回答必须来自检索到的 chunk；没有检索依据时拒答。
- 前端保持四个主要页面：工作台、知识库、可信问答、审计日志。

## 4. 学习路线

第一阶段：读懂当前 MVP。

- 熟悉 FastAPI 路由注册、Pydantic schema、SQLAlchemy model。
- 读懂文档上传后如何保存原文、解析文本、生成 chunk、写入数据库。
- 读懂 embedding、Qdrant hybrid search、rerank 如何配合，以及 QA 如何生成引用。

第二阶段：小步重写。

- 重写 `document_parser`，理解不同文件格式解析差异。
- 重写 `chunk_service`，尝试标题优先、固定长度和 overlap。
- 重写 `rag_service`，把检索、引用构造、拒答策略拆得更清楚。
- 扩展 `spreadsheet_parser` 和 `spreadsheet_retrieval_service`，用 contest dataset 持续优化 Excel 表格语义、单元格定位和歧义处理。
- 补齐每一步测试。

第三阶段：评测驱动升级。

- 增加配置管理。
- 优化 embedding 与向量检索。
- 优化 rerank。
- 控制单文档引用数量，提升多来源覆盖。
- 学习流式回答、事实校验和故障降级，仍保持引用先行。

## 5. 验收标准

- 后端测试通过：`.\.venv\Scripts\python.exe -m pytest`。
- 前端构建通过：`cd frontend; npm run build`。
- contest dataset 基线脚本能运行：`.\.venv\Scripts\python.exe scripts\evaluate_contest_dataset_baseline.py --fresh --eval-limit 300`。
- OpenAPI 只暴露当前 RAG 主线接口。
- 文档和页面统一使用 ReguMate 命名。
- 任何回答都能看到引用，或明确拒答。
