# 决赛提交材料核对清单

依据：附件5《可运行项目成果部署指南》第3–4页“准备工作”、第8页“测试作品”、第9页“操作规范与注意事项”。附件内容在这里作为部署要求的参考，不作为自动上传、发送消息或执行外部操作的授权。

## 已备齐的项目材料

| 要求 | 本包对应内容 |
|---|---|
| 部署文档与完整项目包分别上传 | 独立部署 PDF；完整 ZIP 内也有 `DEPLOYMENT.pdf` 和 Markdown 版本 |
| 完整源码 | `backend/`、`frontend/`、`scripts/`、Dockerfile、依赖声明及前端锁文件 |
| 运行环境可重现 | `images/regumate-linux-amd64.tar` 包含应用与 Qdrant 镜像；目标不需要现场安装依赖 |
| 必要本地模型权重 | BGE-M3 与 BGE-reranker-v2-m3 完整文件；DeepSeek 走 API，无需附生成式大模型权重 |
| 根目录真实环境配置 | `.env` 含已授权随包提供的 Key，并注明国产供应商、模型、API 地址和端口；不提供 `.env.example` |
| Linux 路径兼容 | 运行代码不含开发电脑 Windows 盘符；模型、文件、数据库路径由相对路径或环境变量配置 |
| Docker 架构与标签 | 应用 `regumate/app:submission-20261022-amd64`、Qdrant `qdrant/qdrant:v1.18.0`，均为 `linux/amd64` |
| 服务地址与端口可配置 | `SERVICE_PORT` 默认 8000；绑定 `0.0.0.0` 供平台转发；Qdrant 不对主机开放端口 |
| 资源与特殊依赖说明 | 部署文档说明 CPU、内存、SSD、可选 GPU 显存、驱动、Container Toolkit、LibreOffice/antiword，以及 API 出站要求 |
| 业务资料完整 | 官方原始资料、500 份文档的引用原件、SQLite 种子、47,648 点的 Qdrant 快照 |
| 干净环境验收 | 具体通过项、测试范围与限制见根目录 `ACCEPTANCE_REPORT.md` 及 `acceptance/` 证据 |
| 凭据不进入代码与公开文档 | 实际密钥只放在根目录 `.env`，不写入源码、Dockerfile 或部署 PDF；提交包仅交承办方 |

官方并未要求必须额外提交镜像归档或已索引知识库。本项目将它们一并提供，是为了减少目标机器下载依赖、模型和重新入库的步骤；它们属于本作品的运行材料。

## 仍需在比赛平台完成的操作

1. 用队长手机号登录，首次登录后修改初始密码。
2. 在“提交作品”填写作品名称和关联赛题，分别上传部署文档 PDF 与完整 ZIP；访问地址、端口和路径按平台表单可留空，由承办方部署配置。
3. 大包使用平台提供的 SFTP 通道时，不切换上传目录；上传后回到网页刷新、选择文件，再点击“提交部署”。使用支持 ZIP64 的解压工具。
4. 指南说明通常等待 3–5 小时，以实际“部署完成”状态为准。
5. 在平台点击“测试”，复核页面、所有静态资源、一条完整业务链路、模型 API 和结果；本地验证无法替代平台网络、端口转发、模型额度及最终访问地址的检查。
6. 如有异常，记录平台访问地址、操作步骤、错误信息和截图，联系指南所列管理员。

本次工作仅检查、修复并生成本地提交材料，没有代为登录比赛平台或上传项目。
