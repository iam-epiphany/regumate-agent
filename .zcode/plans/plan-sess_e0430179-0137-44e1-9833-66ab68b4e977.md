# 计划：跨文档检索能力增强——文件覆盖优先策略

## 背景（断点已精确定位）

跨文档题（X01/X02/X03/X04，v6 稳定失败）的共同断点：**检索的 rerank 输入阶段就被单文件垄断**（X03 实测：27 个候选全部来自"消费金融公司管理办法"，金标要求的"资本工具合格标准"文件完全未进入 rerank）。现有文件多样性机制 `_select_final_chunks → _limit_document_repetition` 有两个缺陷：
1. 仅按触发词启用（"综合/总结/对比/比较/区别/关系/不同"）——X01/X02 的"**是否一致**"、X03 的"应当符合"都不触发
2. 触发时"每文件限 2 个"过度裁剪（故默认不启用，会削薄单文件题）
3. 施加位置太晚（rerank 之后），X03 的第二文件在 rerank 输入（top-24）就已消失

## 修复（通用能力，两层文件覆盖）

**新增"文件覆盖优先"选择器**（每文件最高分 1 个 + 按分回填）：
```python
def _select_with_document_coverage(items, limit):
    if len(items) <= limit: return items
    # 第一轮：每文件最高分 1 个（items 已按 _rank_key 排序）→ 保证多文件
    # 问题的每个相关文件至少进入证据
    # 第二轮：按分数回填剩余配额 → 单文件问题自然补满（不削薄）
```

**第一层（rerank 输入）**：`retrieval_support.py _finish_aspect_matches` 的 `rerank_input` 构造（当前 `limit_rerank_candidates`）改为文件覆盖优先——保证第二文件进入 rerank 候选（X03 类隐含跨文档）。

**第二层（最终选择）**：`retrieval_service.py _select_final_chunks` 默认走文件覆盖优先（替代触发式 `_limit_document_repetition`；函数保留但不再作为唯一路径）——保证第二文件进入最终证据（X01/X02 类）。

单文件题无副作用：第一轮仅 1 个/文件，回填补满至 limit，结果与现状一致。
MCQ 走 `_mcq_matches_from_reranked` 独立路径（自带 document_coverage），不受影响。

## 验证

1. 新增单测（换题构造）：
   - 多文件相关时第二文件至少 1 个进最终证据（X03 同型：问题提 A 文件，B 文件相关）
   - 单文件题不削薄（top-12 仍来自同一文件且数量不变）
   - 显式双文件对比（X01 同型：2 个文件名 + "是否一致"）
2. 全量 pytest 全绿 + 反硬编码审计 0 发现
3. 容器重建 → **官方 300 回归（必须 300/300）**（文本题 200 题全走此路径，重点验证；MCQ 100 题不受影响）
4. workbench 100 对比：X 类（X01/X02/X03/X04）是否恢复；证据命中率是否再提升
5. 更新报告
